## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → recordings reader | Org-scoped synced-status query; a missing org filter leaks cross-org status |
| provider API → surface | searchAvailable returns untrusted external ids rendered into the table |
| one provider's status batch → other providers' rows | merge boundary; a clobber would corrupt unrelated rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-02-ID | Information Disclosure | importSurfaceSyncStatus.ts overlay | mitigate | Thread organizationId into getSyncStatusForExternalIds (WR-02) so a user in multiple orgs cannot read another org's synced status. RLS already bounds recordings/workspace_entries. |
| T-26-02-T | Tampering | external id handling | mitigate | externalId treated as opaque TEXT end-to-end; never parseInt/Number (dual recording-ID rule). Grep-gated to 0. |
| T-26-02-DI2 | Information Disclosure | per-provider scoping | mitigate | Browse-synced section scoped to the surface's sourceApp; surface never queries other providers' rows when scoped to one provider. |
| T-26-02-Integrity | Tampering | merge vs clobber | mitigate | Overlay flips synced only on a hit; rows outside a provider's batch are never reset (WR-01) — asserted by a passing two-provider test. |
</threat_model>
