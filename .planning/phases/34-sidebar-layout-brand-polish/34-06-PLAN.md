# 34-06 — Cleanup

Four remaining items grouped — each is small but distinct.

## BRAND-07 — Doubled X close button

CONTEXT.md cites Phase 29 Image #7. Per code inspection, shadcn `Dialog` (radix-ui based) renders a built-in close X in the top-right via `DialogContent` (an automatic `<DialogPrimitive.Close>` with `<X />` icon). When a custom-styled header inside the dialog (or a `<Sheet>`-like panel) ALSO renders its own close button, you get two X icons.

Most likely offender: `WorkspaceDetailPanel.tsx` lines 109-123 — header has its own `<Button>` with `<RiCloseLine>` (line 120-122). But that panel renders inside Pane 4 (`DetailPaneOutlet`), NOT a Dialog. Pane 4 has no built-in close X.

Check shadcn `dialog.tsx`:
- If `dialog.tsx` auto-adds an X AND some custom dialog uses its own close, that's the duplicate.

Likeliest doubled-X location is a Dialog with a custom header that adds its own close. Search:

```bash
grep -ln "DialogContent" src/components/dialogs/ | xargs grep -l "RiCloseLine" 2>/dev/null
```

Common offenders: `EditWorkspaceDialog`, `CreateWorkspaceDialog`, `DeleteWorkspaceDialog`. Audit and remove the custom close where the Dialog primitive's built-in close is already present.

## BRAND-08 — Global search modal polish

`src/components/search/GlobalSearchModal.tsx` line 80-113 — the DialogContent uses `p-0 gap-0 max-w-2xl w-full overflow-hidden` and the input is a raw `<input>` inside a `flex items-center` div with `border-b border-border`. Per CONTEXT.md make the search input rounded and brand-consistent (matches Cmd+K dialog elsewhere). Use shadcn `Input` primitive with `rounded-md`.

## BRAND-09 — Memberships section borders

`WorkspaceDetailPanel.tsx` lines 187-201 (Memberships section) wraps members list in `<div className="border border-border/40 rounded-2xl overflow-hidden bg-card/20">` — that's the "stray box" border around the MEMBERSHIPS heading. The heading itself (lines 189-195) sits above the box, but the visual effect creates a heading + box that looks doubly-bordered when combined with WorkspaceMemberPanel's own card chrome. Per CONTEXT.md remove the orphan wrapper border on section headings.

Similar concern: lines 224 (Workspace Info subsection) — same pattern `border border-border/40 rounded-2xl p-4 space-y-3 bg-card/20`.

Decision: drop the redundant outer border on Memberships (let WorkspaceMemberPanel's own chrome handle it), but keep Workspace Info border (it's an info card, not a heading container).

## BRAND-10 — Settings > Organizations header

`OrganizationsTab.tsx` lines 60-64 — header reads `Workspaces / Manage your organizational structure and collaboration workspaces`. Wire to the active org so it reads e.g. `AI Simple / Your personal organization for private recordings` (per CONTEXT.md sample).
