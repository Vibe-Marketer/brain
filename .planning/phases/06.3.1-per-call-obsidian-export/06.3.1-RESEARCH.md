# Phase 06.3.1 Research: Per-call Obsidian Export

## User Constraints

- Phase 06.3.1 adds a per-call Obsidian export action from an individual call/transcript surface; it must not add an Obsidian plugin, restore `obsidian-sync`, change API-token semantics, change full-vault ZIP behavior except shared utility extraction, or touch the Phase 06.3.2 `legacy_recording_id` rename. [VERIFIED: CONTEXT.md]
- The action belongs in an existing call/transcript action menu or export menu as `Export to Obsidian`, not Settings and not a large primary button. The flow should be action-first and one-click where possible. [VERIFIED: CONTEXT.md]
- Primary output is one standalone `.md` file for the current call, not a ZIP or browser-downloaded folder tree. [VERIFIED: CONTEXT.md]
- The note must follow the full-vault Obsidian conventions: YAML front matter, readable call note body, `# {title}`, date, duration when known, workspace when known, participant wikilinks when known, optional summary, and `## Transcript`. [VERIFIED: CONTEXT.md]
- Filename should follow the existing Obsidian convention: `{date}-{slug}.md`, with filesystem-safe slugging and deterministic fallback. `vault_path` can represent the recommended destination path `CallVault/{org}/{workspace}/{date}-{slug}.md`. [VERIFIED: CONTEXT.md]
- Add `Copy Obsidian markdown` only if cheap and consistent with existing menu patterns; download-only is acceptable and must not be blocked by clipboard scope. [VERIFIED: CONTEXT.md]
- Carry Phase 06.3 metadata forward: title, date/date_time, duration, organization/workspace when available, participants, tags if available, transcript presence, canonical UUID, share/source URL when available, and synced/exported timestamp. [VERIFIED: CONTEXT.md]
- Prefer canonical UUID identity; do not introduce new numeric Fathom-ID dependencies. Preserve stored transcript text and do not synthesize false speakers/timestamps. Missing transcript renders `Transcript not available.` [VERIFIED: CONTEXT.md]
- Reuse/extract `src/lib/export-utils.ts` Obsidian markdown construction so full-vault and per-call exports do not drift. Preserve service + hook/component separation. [VERIFIED: CONTEXT.md]
- Keep copy in the "AI-ready, not AI-powered" lane. [VERIFIED: CONTEXT.md]
- Add focused builder/export tests plus UI/hook verification for download and copy if included. Run `npm run type-check` and `npm run build`; UI changes need browser/screenshot verification. [VERIFIED: CONTEXT.md]
- Deferred: full Obsidian plugin, `obsidian-sync`, Obsidian-specific token source, full-vault scale hardening beyond shared helper needs, and Phase 06.3.2 provider-ID rename. [VERIFIED: CONTEXT.md]

[VERIFIED: codebase]
- Current `exportToObsidian(calls, orgName, excludedWorkspaceNames)` creates a JSZip archive, writes one markdown file per filtered call under `CallVault/{org}/{workspace}/{date}-{slug}.md`, suffixes duplicate paths, and saves `callvault-obsidian-{date}.zip`. [VERIFIED: codebase]
- Current Obsidian front matter already includes `callvault_id`, `type`, `date`, `date_time`, `duration_min`, `organization`, `workspace`, `vault_path`, `word_count`, `participants`, `tags`, `has_transcript`, optional `share_url`, and `synced_at`. [VERIFIED: codebase]

- The Obsidian builder is private, so the plan should extract pure exported helpers before wiring UI. Recommended helpers: `buildObsidianFileName(call)`, `buildObsidianVaultPath(call, orgName, workspaceName, suffix?)`, `buildObsidianMarkdown(call, options)`, and `exportSingleCallToObsidian(call, options)`. [VERIFIED: codebase] [ASSUMED]

## Common Pitfalls

- The Obsidian helper functions are currently private; tests cannot directly target front matter/body construction until exports are added. [VERIFIED: codebase]
- There is no current `src/lib/__tests__/export-utils.obsidian.test.ts` in the working tree, despite Phase 06.3 planning references. The planner should schedule new utility tests rather than relying on existing Obsidian utility coverage. [VERIFIED: codebase]
- `src/lib/export-utils.ts` is already modified in the working tree by someone else, improving YAML string escaping and passing `vaultPath` into `buildObsidianFrontmatter()`. Implementation must preserve and build on that work, not revert it. [VERIFIED: codebase]
- `useTranscriptExport()` metadata currently says `Fathom Share Link` and reads only `call.share_url`; it should not be the source of Obsidian source URL behavior without adapting to `resolveShareUrl()`. [VERIFIED: codebase]
- `CallDetailDialog` destructures `callTags` as `_callTags` and does not pass tags to the transcript tab/export hook. Tags are fetched nearby but not currently available to `CallTranscriptTab`. [VERIFIED: codebase]
- `Meeting` does not include `workspace_name` in its base type, while `ExportableCall` adds `workspace_name?: string | null`. Per-call export may need a narrow adapter or type extension for workspace name. [VERIFIED: codebase]
- `useCallDetailQueries()` can parse `full_transcript` into display segments and can fall back to fetching transcripts; per-call Obsidian should prefer stored `call.full_transcript` or a faithful reconstruction only if the stored text is missing. [VERIFIED: codebase] [ASSUMED]
- Clipboard writes can fail because of browser permissions/user gesture requirements; copy support must catch errors and toast failure, like existing `handleCopyTranscript()`. [VERIFIED: codebase] [ASSUMED]
- UI buttons in `CallTranscriptTab` are already dense; adding two more full text buttons could overflow on smaller modal widths. Prefer either one `Export to Obsidian` action plus optional compact copy, or a small dropdown/popover if implementation touches this row. [VERIFIED: codebase] [ASSUMED]
