## Data Flow

1. `CallDetailDialog` owns the current `Meeting`, transcript display data, duration, speakers, tags from `useCallDetailQueries()`, and the existing export hook call.
2. `useTranscriptExport()` should adapt the current call into `ExportableCall` and call exported Obsidian helpers from `src/lib/export-utils.ts`.
3. `CallTranscriptTab` should receive handlers only; it should not build markdown, call `saveAs`, or fetch metadata.
4. `export-utils.ts` should own filename, recommended vault path, front matter, body markdown, transcript fallback, and `saveAs` for the `.md` file.

## Concrete Source Constraints

- `exportToObsidian()` currently creates ZIP paths as `CallVault/{org}/{workspace}/{date}-{slug}.md`, suffixes duplicate paths, builds YAML front matter with `callvault_id`, `type: call`, `date`, `date_time`, `duration_min`, `organization`, `workspace`, `vault_path`, `word_count`, participant wikilinks, tags, `has_transcript`, optional `share_url`, and `synced_at`.
- Obsidian export already preserves structured transcript output through `getExportTranscriptText(call)`, which prefers `transcript_segments` before `full_transcript`.
- The generic `exportToMarkdown()` path is not a correct analog for this phase because it uses `generateMarkdownContent()` and `transcriptToMarkdown()`, which can reformat transcript text. Use the Obsidian-specific code path instead.
- `useTranscriptExport()` currently labels the source URL as `Fathom Share Link` and reads only `call.share_url`; per-call Obsidian export must not inherit that Fathom-specific wording or lookup.
- `CallTranscriptTab` imports `resolveShareUrl()` for display, proving the canonical source URL helper is already available near the UI surface.
- `CallDetailDialog` currently destructures `callTags` as `_callTags`; if tags are included in per-call front matter, the plan must explicitly thread them or accept a scoped fallback.
- Existing `src/lib/__tests__/export-utils.obsidian.test.ts` already mocks `jszip` and `file-saver`, covers ZIP paths, duplicate suffixes, front matter, YAML escaping, missing transcript text, structured transcript preference, and 5,000-call output.

## Risks and Checks

- **Formatting drift:** Block by extracting shared helpers and making both ZIP and per-call download use them.
- **UI crowding:** Block by planning a compact action in the existing export row instead of adding multiple long text buttons.
- **Metadata gaps:** Decide explicitly whether org/workspace/tags come from existing props, nearby query data, or stable fallbacks; do not add broad new backend queries for cosmetic metadata.
- **Source URL correctness:** Use `resolveShareUrl()` semantics before setting `ExportableCall.url`.
- **Scope creep:** No `obsidian-sync`, no plugin, no token-source changes, no Phase 06.3.2 rename work, no backend deploy.
