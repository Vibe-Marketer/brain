<objective>
SEN-03: make Sentry errors auto-debugged via a gsd-debug-DISCIPLINED + memory brief, routed into the EXISTING fix loop (D-01 — reuse the loop, do not fork). Per RESEARCH Pitfall 1, `gsd-debug` is interactive and CANNOT run in the daemon's single non-interactive subprocess — so "gsd-debug-disciplined" means embedding the scientific-method discipline as brief TEXT, not a tool call. Per D-05 (LOCKED), memory is a ZERO-PACKAGE JSONB prior-attempt history (NO `@honcho-ai/sdk`, NO `bun add`), read from existing DB state and injected into the brief.

Purpose: a re-attempt on the same Sentry fingerprint must see what was tried and failed last time (so the agent does not repeat dead hypotheses), and must apply disciplined debugging — without forking the runner and without new dependencies.
Output: a new `sentry-memory.ts` adapter + an extended `composeBrief` that, for `source === "sentry"`, prepends discipline + prior attempts while preserving the load-bearing HARD POLICY block verbatim, plus runner wiring so the generated brief used by the fix attempt actually contains the memory block.

NOTE: work happens in `~/dev/autopilot` (separate repo, no git remote — commits are local-only on this machine per the ownership doc). `autopilot/` is a gitignored symlink in brain for navigation; commit inside `~/dev/autopilot`.
