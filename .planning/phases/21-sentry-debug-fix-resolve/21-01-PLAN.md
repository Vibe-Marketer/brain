(1) `ALTER TABLE public.tickets ADD COLUMN sentry_resolved_at TIMESTAMPTZ;` for SEN-04 cycle time (set later by the resolve path; cycle time = sentry_resolved_at - created_at). COMMENT ON the column.

(2) `CREATE TABLE public.sentry_fingerprint_cap (fingerprint TEXT PRIMARY KEY, fix_attempts INTEGER NOT NULL DEFAULT 0, frozen BOOLEAN NOT NULL DEFAULT FALSE, frozen_at TIMESTAMPTZ, last_attempt_at TIMESTAMPTZ)` per RESEARCH Code Examples / PATTERNS. `fingerprint` holds `sentry:<issue_id>` matching `tickets.fingerprint`. `ENABLE ROW LEVEL SECURITY` with NO policy (deny-all to anon/authenticated is correct — service-role-only, no user columns; PATTERNS RLS note). (3) A SECURITY DEFINER RPC `record_fingerprint_fix_attempt(p_fingerprint TEXT, p_cap INTEGER DEFAULT 3)` that upserts the cap row, increments `fix_attempts`, stamps `last_attempt_at`, and when the post-increment `fix_attempts > p_cap` sets `frozen=true` + `frozen_at=NOW()`. RETURNS the new `fix_attempts` + `frozen`. This is the per-fingerprint cap mechanism that freezes the SINGLE category on the 4th regression (D-03, ≤3 then freeze). REVOKE from PUBLIC/anon/authenticated; GRANT EXECUTE to service_role.

(4) A debounce predicate the autopilot claimer can read. Express it as a SECURITY DEFINER RPC `sentry_ticket_fixable(p_ticket_id UUID, p_min_occurrences INTEGER DEFAULT 3, p_window_minutes INTEGER DEFAULT 15)` returning BOOLEAN: TRUE only when the ticket is source='sentry' AND occurrence_count >= p_min_occurrences AND last_seen_at <= created_at + (p_window_minutes || ' minutes')::interval (recurred enough, within the window — RESEARCH Pattern 3, D-02 ≥3 in 15 min). Non-sentry tickets return TRUE (debounce applies only to sentry). REVOKE/GRANT service_role as above. (RPC chosen over a generated column so the window is tunable without a schema change.)

Use snake_case columns (supabase/CLAUDE.md). Do NOT add a `user_id` to the cap table — it is system state, not user-owned.
