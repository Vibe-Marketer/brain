<objective>
SEN-05 daemon half: the outward-facing resolve write-back, fully gated, plus the independent per-fingerprint cap lifecycle. When the daemon actually attempts an autonomous fix for a Sentry-source ticket (the existing runner_runs attempt/finalization ledger point, and the approval merge point if that is the only place with the final ticket+fingerprint context), record that fix attempt via Plan 01's `record_fingerprint_fix_attempt`; if the RPC returns `newly_frozen=true`, FREEZE that single fingerprint/category (never global) and page Andrew with a solution-shaped tier-2 digest. On every real regression detection (canary/reopen), record the same cap independently of the Sentry resolve API response.

After `executeApproval` merges + verifies the deploy + sets the ticket `status: resolved` (approval.ts ~752-765), for Sentry-source tickets ONLY, gate the OUTWARD Sentry resolve on three conditions (D-03/D-04): (1) the fingerprint is not frozen in `sentry_fingerprint_cap`, (2) `verifyDeploySha` is true (deployed SHA == fix SHA), (3) the 30-min post-deploy quiet window has elapsed. Only then invoke the `sentry-resolve` Edge Function (Plan 02) and stamp `tickets.sentry_resolved_at` (cycle-time close). A Sentry resolve API 4xx/5xx is an API/write-back error to log/page/retry; it is NOT evidence that the fix regressed and must NOT call `record_fingerprint_fix_attempt`.

This plan contains the NO-ANALOG call seam: the autopilot daemon has NO existing Edge-Function-invoke call (it only talks to Postgres tables/RPCs today). The daemon→Edge-Function invocation is genuinely new wiring (RESEARCH A4, PATTERNS "No Analog Found") — it carries a blocking checkpoint.

Purpose: D-04 — resolving a real issue on the live `ai-simple` org is irreversible-ish; the write-back path must be gated, idempotent, and fire ONLY on verified-stable deploys. Never resolve-on-merge (manufactures false-regression storms). The cap is the anti-oscillation guard (Pitfall 3).
Output: `sentry-resolve.ts` daemon caller + the executeApproval tail hook + tests; the invoke-seam choice confirmed via checkpoint.

NOTE: work in `~/dev/autopilot` (separate repo; commits local-only). Requires Plan 01 schema-pushed (cap RPC + sentry_resolved_at) AND Plan 02's function deployed with secrets.
