## Visual Hierarchy

The reconciled transcript text is the primary focal point of the "Reconciled" tab — it reads exactly like the existing per-recording transcript view (same typography, same scroll behavior). `ReconciledSegmentProvenanceBadge` markers are secondary metadata: small, `text-muted-foreground`, inline at the end of a segment, never competing with the transcript text itself for attention. Single-source segments render with zero visual distinction from the surrounding text — provenance is opt-in-to-notice, not foregrounded.

## Architecture Notes (UI Surface Attachment)

There is no existing "event" nav surface in the app — `src/pages/` has no `EventPage`. Per `37-CONTEXT.md`'s discretion note, this is resolved as follows:

- **Attachment point: a new tab inside the existing `CallDetailDialog` modal**, not a new route or nav-rail item. `AppShell`'s own documented rule (`Modal vs Pane 4 Rules`) classifies "Full call detail + transcript" as a modal-overlay concern, not Pane 4 — the reconciled transcript is exactly this: multi-section, scrollable, focused-attention content. This also satisfies the CONTEXT.md rule that "existing per-recording transcript views are untouched" — the new tab sits alongside `CallTranscriptTab`, `CallOverviewTab`, `CallParticipantsTab`, never replacing them.
- **Tab label:** "Reconciled" (short, matches existing tab-label brevity; full label in the tab's own heading: "Reconciled Transcript").
- **Conditional rendering:** the tab renders only when the open call's `event_id` resolves to an event with 2+ recordings that have passed metadata-tier resolution (`event_match_decisions`) AND at least one row exists in the reconciliation table for that event. If the event qualifies but reconciliation hasn't swept yet, the tab still renders (so its existence isn't itself a leak of reconciliation timing) but shows the pending state — see Copywriting Contract.
- **Entry-point affordance:** `CallDetailHeader` gains a small `Badge` (outline variant, same visual weight as `RoutingTraceBadge`) reading "N recordings" when the call's event has 2+ resolved recordings, giving the user a reason to look for the new tab. This is informational, not a new CTA — the tab itself is the destination.
- **New standalone component:** `ReconciledSegmentProvenanceBadge` (in `src/components/call-detail/` or `src/components/shared/`, naming at executor's discretion) — mirrors the `RoutingTraceBadge`/`IdentityEvidenceBadge` popover pattern exactly (icon-only trigger, `Popover` from `@radix-ui/react-popover` or the shadcn `popover.tsx` wrapper, `w-64 p-3` content). Rendered inline per-segment, **only on multi-source/consensus segments** — single-source segments render with zero badge, per CONTEXT.md ("single-source segments carry no special badge — they simply are the source").
- **Icon choice:** `RiGitMergeLine` for the consensus/multi-source badge trigger (semantically distinct from `RiNodeTree` already used for routing-rule provenance and `RiShieldCheckLine` already used for identity evidence — avoids icon collision across the three provenance-badge families now in the app).

## UI Considerations

Applicable state considerations resolved: 6 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Reconciled tab content | ✅ covered | Renders the "Reconciliation pending" empty state (see Copywriting Contract) when the event qualifies (2+ resolved recordings) but no reconciled-segment rows exist yet for it. |
| loading | Reconciled tab content | ✅ covered | Uses the existing `Skeleton` component (`@/components/ui/skeleton`), matching the loading pattern already used by `IdentityEvidenceBadge`'s popover — no new loading primitive. |
| error | Reconciled tab content | ✅ covered | Renders the "Couldn't load" error state (see Copywriting Contract) on fetch failure; per-recording tabs remain fully usable as a fallback, satisfying the non-destructive-UI principle. |
| partial (coverage gap) | Single-source segment intervals | ✅ covered | Per RECON-06/CONTEXT.md: single-source intervals render with zero provenance badge — they are visually indistinguishable from a normal transcript segment, which IS the "not consensus" signal (absence of a badge = single source, by design, not an omission). |
| zero-one-many | Provenance badge (# of agreeing sources) | ✅ covered | Badge only renders for segments with 2+ agreeing sources (multi-source/consensus); a segment with exactly 1 source renders no badge (covered above); the popover body correctly pluralizes "N recordings" for N≥2. |
| tab visibility (zero-one-many recordings) | "Reconciled" tab trigger | ✅ covered | Tab is entirely absent (not disabled, not shown-then-empty) when the call's event has fewer than 2 resolved recordings — matches the existing conditional-tab precedent already in `CallDetailDialog` rather than introducing a new disabled-tab pattern. |
| long-text | Reconciled transcript segment text | 🧪 backstop | Long single-token or long-segment text is expected to wrap normally within the existing `ScrollArea`-bound transcript layout (same wrapping behavior as `CallTranscriptTab`) — held out as a backstop since it inherits, rather than redefines, existing transcript-rendering behavior; verify visually against a long real segment at implementation time. |
| overflow (many sources on one segment) | Provenance popover source list | 🧪 backstop | An event resolving many recordings (edge case, e.g. 5+ copies of one call) could produce a popover body list longer than the `w-64` popover comfortably shows — held out as a backstop; if it proves common, cap the visible list and add "+N more" truncation matching existing popover conventions. |
