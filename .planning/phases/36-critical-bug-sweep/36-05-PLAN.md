# Plan 36-05: BUG-09 — DialogDescription on Every Modal

## Goal

Console shows zero `DialogContent` accessibility warnings. Every Radix Dialog has a `<DialogDescription>` — visible where it adds value, or wrapped in `<VisuallyHidden>` when the description is implicit.

## Background

Radix UI emits a console warning when a `DialogContent` has no `DialogDescription` (or no `aria-describedby`). Modals affected: Add Workspace, Delete Workspace, Disconnect Source, Create Org, Smart Export, Paste Transcript, every confirm/alert dialog, search/cmdK, and call-detail modal.

<action>
For every file in the T1 list, add a `<DialogDescription>` (or `<AlertDialog.Description>`) inside the `<DialogContent>`. Rules:

1. **Visible description preferred** — if the dialog has a natural one-line subtitle (e.g., "Disconnect Fathom?" → "Your imported calls will remain in CallVault"), surface it as a real visible `<DialogDescription>` rendered below the title.
2. **VisuallyHidden fallback** — if the dialog is a tightly focused form where a description would be redundant (e.g., a 1-field rename), wrap the description in `<VisuallyHidden>` (from `@radix-ui/react-visually-hidden`) and write a concise screen-reader-only sentence: `"Rename this workspace."`
3. NEVER suppress the warning without adding a real description. The warning is a real a11y gap.

For each file, the description text must reflect what the dialog actually does. Do NOT use generic placeholders like "Dialog description."

Example (rename dialog):
```tsx
import * as VisuallyHidden from '@radix-ui/react-visually-hidden'
// ...
<DialogContent>
  <DialogTitle>Rename workspace</DialogTitle>
  <VisuallyHidden.Root>
    <DialogDescription>Update the workspace name.</DialogDescription>
  </VisuallyHidden.Root>
  {/* ... */}
</DialogContent>
```
</action>
