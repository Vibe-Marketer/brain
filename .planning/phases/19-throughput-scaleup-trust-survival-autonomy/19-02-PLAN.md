<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser admin -> Edge Function | An authenticated browser requests privileged category rung mutation |
| Edge Function -> service-role Supabase | Server performs trusted writes to ladder/audit tables |
| metrics RPC -> Dashboard UI | Operational trust data renders in an admin-only frontend |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-06 | Elevation of Privilege | `autopilot-trust-admin` | mitigate | Verify JWT with `authenticateRequest`, verify ADMIN via service-role `has_role`, ignore actor from body. |
| T-19-07 | Repudiation | promotion/demotion | mitigate | Write `autopilot_trust_events` and `admin_audit_log` for every mutation. |
| T-19-08 | Tampering | auto promotion | mitigate | Return 409 unless category meets survival gate and admin explicitly requested promotion per D-03. |
| T-19-09 | Information Disclosure | Dashboard trust card | mitigate | Fetch only through admin-gated RPC; no reporter-facing component imports trust metrics. |
| T-19-SC | Tampering | package installs | accept | No new packages; use existing zod from Edge Function pattern and existing UI primitives. |
</threat_model>
