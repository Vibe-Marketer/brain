<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migration author -> production Postgres | Durable trust state and admin RPCs are added to the live database |
| browser admin -> `autopilot_trust_metrics()` | Authenticated browser callers can ask for operational trust metrics |
| autopilot service-role -> trust tables | Daemon can later write trust state that drives approval authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Elevation of Privilege | `autopilot_category_trust.rung` | mitigate | Schema separates computed `eligible` from stored `auto`; later promotion must be explicit admin mutation and audited per D-03. |
| T-19-02 | Information Disclosure | trust tables and metrics RPC | mitigate | RLS admin SELECT only, no browser write policies, RPC internal `has_role` guard, PUBLIC/anon execute revoked. |
| T-19-03 | Tampering | survival denominator | mitigate | RPC requires merged fix identity and matured survival window and excludes `deferred:rate-limit` per D-05. |
| T-19-04 | Repudiation | category promotion/demotion history | mitigate | Append-only `autopilot_trust_events` captures actor, category, old/new values, and metadata. |
| T-19-05 | Tampering | canary attribution | mitigate | `runner_runs.reopened_event_id` references `ticket_events(id)` so canary reopen links to the originating ticket/run per D-04. |
| T-19-SC | Tampering | package installs | accept | No package installs are planned. |
</threat_model>
