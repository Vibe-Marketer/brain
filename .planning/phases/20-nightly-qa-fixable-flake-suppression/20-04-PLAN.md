<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser admin UI -> Supabase RLS | Authenticated browser reads operational QA finding state. |
| Service layer -> component layer | Data shape crosses from pure services into UI rendering. |
| QA finding message -> operator display | Untrusted crawler text may be shown in admin UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-19 | Spoofing | QA UI source labels | mitigate | Use DB source values and existing `ticketSourceLabel`; do not trust finding source text. |
| T-20-20 | Tampering | browser writes | mitigate | Add read-only service functions only; no `qa_findings` browser mutations. |
| T-20-21 | Repudiation | review lane display | mitigate | Show occurrence_count and last_seen_at from DB ledger. |
| T-20-22 | Information Disclosure | crawler messages | mitigate | Display capped concise messages; no secrets; admin-gated RLS only. |
| T-20-23 | Denial of Service | large findings list | mitigate | Limit latest rows and keep pagination/limits in service calls. |
| T-20-24 | Elevation of Privilege | admin QA reads | mitigate | Depend on `has_role(auth.uid(),'ADMIN')` RLS; no client-side-only gate. |
| T-20-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs; Remix Icons only if icons are needed. |
</threat_model>
