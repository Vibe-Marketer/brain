<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Crawler report -> triage | Untrusted browser observations decide whether ticketing is attempted. |
| Triage -> Supabase service role | Local daemon writes ledger/RPC data with elevated credentials. |
| Triage -> subprocess rerun | Finding route/selector data influences crawler invocation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-07 | Spoofing | `triage.ts` RPC payload | mitigate | Do not pass source to RPC; tests cover spoofed finding payloads. |
| T-20-08 | Tampering | route rerun subprocess | mitigate | Use argv arrays, fixed cwd, timeout, and route allow/cap from crawler contract; no shell interpolation. |
| T-20-09 | Repudiation | `qa_findings.repro_attempts` | mitigate | Store rerun exit/report/matched fingerprint evidence for every quarantine/review/promotion decision. |
| T-20-10 | Information Disclosure | logs and runs.log | mitigate | Never log service-role keys or login credentials; cap finding messages in logs. |
| T-20-11 | Denial of Service | rerun loop | mitigate | Default N=2, route-scoped reruns, hard timeout, and no run-cap/concurrency increase. |
| T-20-12 | Elevation of Privilege | `qa_review` lane | mitigate | Keep review/quarantine in `qa_findings`, not `tickets.status='new'`. |
| T-20-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages; use existing Bun, tsx, Playwright, Supabase JS. |
</threat_model>
