<objective>
Build the durable client-side selection store — the root-cause fix for "the selections were GONE." Selection moves out of volatile React `useState` (the `ConnectorImportWizard.tsx` and `useSyncTabSelection.ts` bug sources) into a Zustand store wrapped in the `persist` middleware, persisted to `sessionStorage`, keyed by provider (`source_app`) + date range. Includes the select-all-matching-filter descriptor (SEL-02) and clear-on-job-creation semantics.

Purpose: Selection durability across navigation, unmount, date-range change, and the OAuth round-trip is impossible to break by construction once selection lives in persisted storage instead of component state. This is the foundation Phase 26's `<ImportSurface>` consumes.

Output: `src/stores/importSelectionStore.ts` (store + exported types + key/scope helpers) and its unit test file. This plan delivers SEL-01's durable store + SEL-02's representation. The synced-auto-drop reconciliation clause of SEL-01 lands in Plan 02 (the hook).
</objective>

STORAGE BACKEND = sessionStorage (verified, SEL-01).
- The OAuth return for these connectors is a SAME-TAB FULL-PAGE REDIRECT, not a popup/postMessage flow. Verified in src/components/connectors/setup/ConnectorSetupCluster.tsx:302 (`window.location.href = authUrl`) and src/pages/ImportPage.tsx:78-134 (the return is read from `window.location.search` query params on component MOUNT — i.e. the SPA boots fresh and the persisted store must rehydrate from storage on boot).
- sessionStorage survives a same-tab full-page redirect AND in-app navigation/unmount, and clears when the tab closes (so stale selections do not linger across days). This satisfies all four SEL-01 survival cases. Use sessionStorage, NOT localStorage. State this choice in the SUMMARY.

PERSIST MIDDLEWARE (verified): the codebase does NOT currently use `zustand/middleware` anywhere — orgContextStore.ts hand-rolls localStorage. The locked CONTEXT.md decision is to use the `persist` middleware (zustand 5.0.11 ships `zustand/middleware`). Follow the v5 double-invocation syntax already used in orgContextStore.ts: `create<T>()(persist((set, get) => ({...}), { name, storage }))`.

SELECT-ALL-MATCHING REPRESENTATION = filter descriptor, NOT enumerated ids (verified, SEL-02).
- The provider search is CURSOR-PAGINATED and UNBOUNDED: ConnectorImportWizard.tsx pages via `nextCursor` ("Load more") and only ever holds the rows paged into memory. You CANNOT enumerate all matching ids without paging the entire provider — that is exactly Phase 28's server-side job, deliberately not done here.
- Therefore "select all matching the current filter" is stored as a descriptor `{ mode: 'all-matching', filter: <the active search filter> }` for the scope, NOT a materialized id array. Enumerated explicit selections coexist (the per-row checkbox set). State this choice + reason in the SUMMARY.
</verified_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser tab ↔ sessionStorage | Persisted selection is written to per-tab browser storage on the user's machine. Shared-machine / multiple-user-on-one-browser is the surface. |
| selection store ↔ server truth | The store holds INTENT (call ids the user picked). It is never the authority for "is this synced" — that is `recordings` via Phase 24's reader (reconciled in Plan 02). |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Information Disclosure | persisted selection in browser storage | mitigate | Use `sessionStorage` (clears on tab close) under a single namespaced key `callvault-import-selection`, so selections do not linger across days on a shared machine. Stored values are call IDs (`source_call_id`), NOT secrets/tokens/PII content — low sensitivity. Document this in the SUMMARY. |
| T-25-02 | Tampering | scope keys crossing orgs/providers | mitigate | Scope is keyed by `source_app` + date range; selection is read back only for the active scope, so a tampered/stale scope simply yields an empty selection (fail-safe). Org isolation for the ACTUAL import is enforced server-side (RLS on `sync_jobs`/`recordings`), not in client state — the store cannot authorize an import it isn't entitled to. |
| T-25-03 | Tampering | npm installs | mitigate | NONE — zero new packages (zustand 5.0.11 already installed; `persist` ships with it). No package-legitimacy gate needed. |
| T-25-SC | Tampering | supply chain | accept | No new dependencies introduced this phase; nothing to verify. |
</threat_model>
