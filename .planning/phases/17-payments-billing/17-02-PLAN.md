    - Validate actionType is one of: 'smart_import', 'auto_name', 'auto_tag', 'chat_message'
    - Compute monthYear = new Date().toISOString().slice(0, 7) (e.g., '2026-03')
    - Step 1: Check current usage via RPC get_monthly_ai_usage(user.id, monthYear)

    - Step 4: If currentUsage >= limit, return 429 { error: 'Monthly AI action limit reached', usage: currentUsage, limit, tier }
    - Step 5: If under limit, INSERT into ai_usage table (user_id, org_id, action_type, recording_id, month_year, created_at)
    - Step 6: Return 200 { success: true, usage: currentUsage + 1, limit, remaining: limit - currentUsage - 1 }
    - Use service role supabase client (not user JWT client) for the insert since RLS only allows user reads
    - Actually, RLS allows user inserts too (WITH CHECK auth.uid() = user_id). But since we're using service role for the profile lookup anyway, use service role throughout.
    - Use getCorsHeaders from _shared/cors.ts

    Create src/hooks/useAiGate.ts:
    - Export type AiActionType = 'smart_import' | 'auto_name' | 'auto_tag' | 'chat_message'
    - Export interface AiGateResult { canUse: boolean, trackAction: (type: AiActionType, opts?: { recordingId?: string, orgId?: string }) => Promise<{ allowed: boolean, usage: number, limit: number, remaining: number }>, tier: SubscriptionTier, limit: number, isLoading: boolean }
    - Export function useAiGate(): AiGateResult
    - Internally uses useSubscription() for tier and limit
    - canUse is a quick check: true if tier !== 'free' || (we haven't hit the limit). Since we don't cache usage count here (that's useAiUsage from plan 01), canUse defaults to true and the real gate is trackAction's response.
    - trackAction function:
      a. Gets session via supabase.auth.getSession()
      b. Calls supabase.functions.invoke('track-ai-usage', { headers: { Authorization: `Bearer ${token}` }, body: { actionType, recordingId, orgId } })
      c. If response status 429: show toast.error('Monthly AI limit reached. Upgrade for more.'), invalidate ['ai-usage'] query key, return { allowed: false, usage, limit, remaining: 0 }
      d. If success: invalidate ['ai-usage'] query key (so useAiUsage refetches), return { allowed: true, usage, limit, remaining }
      e. On error: log error, return { allowed: true } as fallback (don't block user on tracking errors)
    - Import toast from sonner for limit-reached notification
    - Import useQueryClient from @tanstack/react-query for cache invalidation

    This hook is the contract that all AI-consuming features will call before executing AI operations. The actual integration into specific features (auto-tag, smart-import, etc.) is future work — this plan just creates the enforcement mechanism.
