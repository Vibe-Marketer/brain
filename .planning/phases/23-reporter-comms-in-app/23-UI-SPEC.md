# Phase 23 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui on Vite |
| Preset | `components.json`: default style, slate base color, CSS variables, `@/` aliases |
| Component library | Radix-backed shadcn primitives already installed |
| Icon library | Remix Icons only (`@remixicon/react`). Do not follow shadcn info's lucide default. |
| Font | Inter for body, Montserrat only where existing pane headings already use it |

### Existing Surface Contract

Phase 23 must land inside existing app surfaces:

| Surface | Contract |
|---------|----------|
| Top bar / app shell | Add the mounted in-app notification entry point here because `useNotifications` exists but no current consumer is mounted. Use an icon-only bell button with `RiNotification3Line`, an unread dot/count, and a popover panel. No new route. |
| Notification panel | Display reporter comms from `user_notifications` with title, body, relative time, read state, and optional `View report` action when metadata contains a reporter-visible ticket id. |
| Existing ticket views | If a reporter-visible ticket detail/list surface is present or added in this phase, reuse existing ticket status badges and detail dialog patterns. Do not create a standalone reporter comms route. |
| Admin ticket views | Admin/operator language may stay admin-only. Do not reuse admin escalation blocks for reporters because existing admin copy contains internal "autopilot" / "agent" language. |

### Reporter Visibility Gate

Only authenticated in-app reporters may see these customer comms. UI must treat backend/RLS/source gating as authoritative and must not show reporter comms for `manual`, `sentry`, `nightly_qa`, `internal`, `unknown`, null, or ambiguous source tickets. If metadata is missing or uncertain, render the notification as a generic app notification or hide the ticket action; never infer it is reporter-safe.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, unread dot offsets, compact metadata gaps |
| sm | 8px | Notification row gaps, popover padding, badge gaps |
| md | 16px | Default panel padding and row horizontal padding |
| lg | 24px | Section padding inside ticket detail/status blocks |
| xl | 32px | Empty state vertical spacing |
| 2xl | 48px | Loading and empty state height |
| 3xl | 64px | Not used in this phase |

Exceptions: icon-only notification button must stay 32px minimum on desktop and 40px minimum on touch/mobile; unread dot may be 8px.

## Typography

Use only these sizes for new Phase 23 UI. Existing shared components may keep their existing typography.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.4 |
| Heading | 16px | 600 | 1.25 |
| Display | 20px | 600 | 1.2 |

Rules:

- Notification titles use 14px / 600.
- Notification bodies use 14px / 400 and clamp at 2 lines in the panel list.
- Metadata such as relative time uses 12px / 400 with `tabular-nums` where numeric.
- Do not use all-caps for reporter-facing reassurance copy. Keep all-caps only for existing badges/section labels.

## Color

Use semantic Tailwind tokens, not hardcoded hex values in implementation. Hex values below document the resolved light-mode intent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-viewport` / `#FCFCFC` | Page gutters behind existing shell |
| Secondary (30%) | `bg-card` / `#FFFFFF`, `bg-muted` / `#F2F2F2` | Notification popover, rows, empty state containers, ticket status blocks |
| Accent (10%) | `text-vibe-orange` / `bg-vibe-orange` / `#FF8800` | Unread count, focus rings, selected notification accent, `View report` text button |
| Destructive | `text-destructive` / `#DC0B0B` | Delete notification only, if surfaced |

Accent reserved for: unread indicator/count, focus ring, active notification row accent, primary text action (`View report`), and existing brand page label. Do not use vibe orange for every interactive element.

Semantic status colors:

| Status | Visual Treatment |
|--------|------------------|
| Received | Existing `StatusBadge` `new` or an info-tinted row icon |
| In progress | Existing `StatusBadge` `active` |
| Resolved | Existing `StatusBadge` `success` |
| Escalated | Existing `StatusBadge` `warning` for reporter-facing reassurance, not `error` unless the action is destructive |

## Copywriting Contract

Reporter-facing copy must pass the default-deny customer copy filter before display. Do not display the words `AI-powered`, `agent`, `Autopilot`, `Codex`, `Claude`, `LLM`, `model`, `prompt`, `token`, `runner`, `worktree`, `branch`, `diff`, `push-gate`, `Sentry`, `stack`, `trace`, `deploy SHA`, file paths, SHAs, stack traces, or code formatting.

| Element | Copy |
|---------|------|
| Primary CTA | View report |
| Empty state heading | No updates yet |
| Empty state body | Ticket updates will appear here when there is something new to share. |
| Error state | Updates could not load. Refresh to try again. |
| Destructive confirmation | Delete update: Delete this update? This only removes it from your notification list. |

### Required Notification Templates

| Kind | Title | Body | Metadata Contract |
|------|-------|------|-------------------|
| received | We received your report | We received your report and are tracking it. | `ticket_id`, `kind: "received"`, `source: "in_app_user"` |
| in_progress | We are working on your report | We are working on your report now. | `ticket_id`, `kind: "in_progress"`, `source: "in_app_user"` |
| resolved | Your report was resolved | This has been fixed and verified in the live app. | `ticket_id`, `kind: "resolved"`, `source: "in_app_user"` |
| resolved_with_summary | Your report was resolved | Use the filtered plain-English summary. If filtering fails, fall back to: This has been fixed and verified in the live app. Thanks for reporting it. | `ticket_id`, `kind: "resolved"`, `source: "in_app_user"`, optional `summary_redacted: true` |
| escalated | We are taking a closer look | We are taking a closer look and will keep tracking this for you. | `ticket_id`, `kind: "escalated"`, `source: "in_app_user"` |

Tone rules:

- Plain, reassuring, and short.
- Never blame the reporter.
- Never expose internal implementation, ownership, or debugging mechanics.
- Never say "a person is looking" unless the underlying state truly means human escalation. Preferred default is "We are taking a closer look."
- Do not tell the reporter to take any action unless there is an explicit customer question/status such as `awaiting_user`.

## Interaction Contract

### Notification Entry Point

- Mount one notification bell button in the existing top bar utility area.
- Use `RiNotification3Line`; if unavailable, use `RiNotificationLine`.
- Button label: `Notifications`.
- Show unread count as a small badge only when unread count is greater than 0.
- Badge displays `9+` for counts above 9.
- Clicking opens a shadcn/Radix popover aligned to the right edge of the top bar.
- Do not toast every reporter comm by default; the notification panel is the durable surface.

### Notification Panel

- Width: 320px desktop, `calc(100vw - 16px)` mobile.
- Max height: 70vh with internal scroll.
- Header row: `Updates` title, optional `Mark all read` text action when unread exists.
- Row layout: icon/status marker, title, body, relative time, unread state.
- Unread rows use `bg-muted/40` and a vibe-orange dot; read rows use `bg-card`.
- Clicking a row marks it read.
- `View report` appears only when metadata contains a reporter-safe ticket id and current user is the reporter.
- Delete action, if retained from hook, is an icon-only `RiCloseLine` or menu action with confirmation copy above.

### Ticket Surface

- Reporter-facing ticket status display must be read-only.
- Show only the status, safe resolution summary, and human-readable escalation status.
- Do not show admin controls, priority, urgent toggle, approval/reject actions, runner evidence, raw event names, raw message authors, console logs, stack traces, file paths, commit SHAs, or technical attachments to reporters.
- If reusing `TicketDetailDialog`, gate all admin/operator sections on role and source. Reporter mode must render a separate "Updates" section backed by sanitized `user_notifications` or safe lifecycle data, not raw `ticket_messages`.

### Status Mapping

| Ticket State/Event | Reporter Label | Reporter Body |
|--------------------|----------------|---------------|
| created/new | Received | We received your report and are tracking it. |
| in_progress | In progress | We are working on your report now. |
| resolved + verified deploy | Resolved | This has been fixed and verified in the live app. |
| resolved + filtered summary | Resolved | The filtered summary, or the fallback resolved body if redacted. |
| escalated | Taking a closer look | We are taking a closer look and will keep tracking this for you. |

## Accessibility Contract

- Notification button has `aria-label="Notifications"` and exposes unread count through visible badge text plus accessible text such as `3 unread updates`.
- Popover title uses a semantic heading.
- All icon-only controls have labels.
- Focus remains trapped only while modal/dialog surfaces are open; notification popover follows existing Radix popover behavior.
- Keyboard: Enter/Space opens the panel, Escape closes it, Tab order enters rows/actions predictably.
- Color is never the only unread/status signal; unread dot/count and text weight must both communicate state.

## Responsive Contract

| Breakpoint | Behavior |
|------------|----------|
| Desktop >1024px | Notification bell sits in top bar utilities after search/theme and before avatar, unless layout spacing requires it before theme. Popover aligns end. |
| Tablet 768-1024px | Same top bar entry point; panel stays 320px or available viewport width. |
| Mobile <768px | Bell remains reachable in top bar utilities. Popover fills available width with 8px viewport margin and does not overlap the safe-area bottom. |

No layout shift: unread count changes must not move adjacent top bar controls.
