# Phase 06.2 Plan 01: API Token Foundation Summary

**One-liner:** SQL RPC for `cv_api_`-prefixed API tokens with partial index, service/hook separation, and settings UI replacing Obsidian-specific token framing.

---

## What Was Built

This plan lays the foundation for the CallVault REST API auth model. Users can now generate and revoke `token_source = 'api'` tokens through the Settings → Integrations surface. The old Obsidian-specific token framing is replaced; users see "API Tokens" and are told to use a CallVault API token with the REST API and the Obsidian plugin.

## Deviations from Plan

None — plan executed exactly as written.

## Known Stubs

None. The token generation flow is fully wired:
- `generate_api_token` RPC is called by `generateApiToken()` service function
- Service is consumed by `useGenerateApiToken` hook
- Hook is consumed by `ApiTokensSection` component
- `IntegrationsTab` renders `ApiTokensSection`

The `fetchAllCallsForObsidianExport` import in `ApiTokensSection.tsx` is a reuse of the existing client-side export utility (not a token-dependent function), and it is fully wired to the "Download all calls" ZIP export button.
