# Phase 06.2 Plan 04: Public REST API Routing, Documentation, and Deploy Summary

**One-liner:** Added /v1/* Cloudflare proxy route to callvault-api, wrote operator runbook with 401/403 smoke contract, deployed with --no-verify-jwt, and live-verified all four smoke behaviors through api.callvaultai.com.

---

## What Was Built

### Task 1: Cloudflare /v1/* route

Added a `/v1/*` branch to `resolveTarget()` in `cloudflare/api-proxy/worker.ts`. The branch forwards to `SUPABASE_BASE/functions/v1/callvault-api${pathname}${search}`. The branch is positioned after the `/auth/v1/*` branch to prevent auth paths from being intercepted. Created `cloudflare/api-proxy/__tests__/worker.test.ts` with 16 tests covering: `/v1/calls`, `/v1/workspaces`, `/v1/contacts`, `/v1/speakers`, `/v1/calls/{id}`, query-string preservation, bare `/v1`, `/auth/v1/oauth/token` isolation, MCP routing regression, and 404 returns. Added `cloudflare/**/__tests__/*.test.ts` to vitest `include` globs so the tests are discoverable.

### Task 2: Operator documentation

Created `docs/operations/api-runbook.md` with:
- Full curl smoke commands for all 5 endpoints
- `{ data, pagination }` and `{ error: { code, message } }` envelope documentation
- 401 (missing/invalid/revoked) and 403 (wrong-source) error shapes with examples
- Token generation, revocation guidance, and deploy commands
- Architecture diagram showing Cloudflare → callvault-api → Supabase flow

Added a "REST API vs MCP — separate protocols" table section to `mcp-runbook.md` clarifying that `/v1/*` (REST, `token_source='api'`) and `/mcp` (MCP, `token_source='mcp'` or OAuth) are distinct surfaces with separate Edge Functions, separate token types, and cross-rejection (HTTP 403).

### Task 3: Deploy and live smoke

- `supabase functions deploy callvault-api --use-api --no-verify-jwt` — deployed successfully
- `npx wrangler deploy` — deployed to `api.callvaultai.com` and `mcp.callvaultai.com`
- Live smoke results through `https://api.callvaultai.com/v1/workspaces`:
  - Valid API token → HTTP 200, `{ data: [...], pagination: { ... } }` confirmed
  - Missing token → HTTP 401
  - Wrong-source MCP token → HTTP 403
  - Revoked token → HTTP 401
- Temporary smoke token (row ID `26c9dfb5`) revoked immediately after testing

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] callvault-api requires --no-verify-jwt**

- **Found during:** Task 3 live smoke
- **Issue:** First smoke attempt returned HTTP 401 with `{"code":"UNAUTHORIZED_INVALID_JWT_FORMAT","message":"Invalid JWT"}`. Supabase's built-in JWT validation ran before the Edge Function handler and rejected the non-JWT API token string.
- **Fix:** Redeployed with `--no-verify-jwt` flag. This is correct — `callvault-api` implements its own token authentication (checks `mcp_tokens` table for `token_source='api'`); Supabase's JWT gate is not needed and actively blocks the intended auth flow.
- **Files modified:** `docs/operations/api-runbook.md` (deploy command updated)
- **Commit:** cc615adf

**2. [Rule 2 - Missing Critical Functionality] Worker tests required vitest include glob update**

- **Found during:** Task 1 test run
- **Issue:** vitest only scanned `src/**/*.test.{ts,tsx}` and `supabase/functions/**/__tests__/*.test.ts`; the new `cloudflare/api-proxy/__tests__/` path was outside the include.
- **Fix:** Added `cloudflare/**/__tests__/*.test.ts` to vitest `include` in `vitest.config.ts`.
- **Files modified:** `vitest.config.ts`
- **Commit:** 35534fae

**3. [Rule 3 - Blocking] Worker tests use inline resolveTarget replica**

- **Found during:** Task 1 test authoring
- **Issue:** Importing `worker.ts` directly into vitest/jsdom fails because the worker uses Cloudflare module syntax incompatible with the jsdom environment.
- **Fix:** Tests use an inline replica of `resolveTarget()`. Any future changes to routing rules in `worker.ts` must be mirrored in the test file's replica. This is documented in the test file comment.
- **Files modified:** `cloudflare/api-proxy/__tests__/worker.test.ts`
