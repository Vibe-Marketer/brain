# Phase 06.2 — UI Design Contract

> Visual and interaction contract for the REST API token/settings surface.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui existing components |
| Preset | Existing CallVault settings surfaces |
| Component library | Radix via shadcn |
| Icon library | Remix Icons only |
| Font | Existing app font stack |

---

## Scope

This UI work is limited to Settings/Integrations or a nearby Developer/API settings surface for creating, viewing, copying once, and revoking API tokens. It must replace the old Obsidian-specific token framing where that framing would teach users the wrong architecture.

The UI must remain dense, settings-like, and action-oriented. Do not create a marketing page, developer portal landing page, or decorative hero.

---

## Layout Contract

| Area | Contract |
|------|----------|
| Section placement | Use the existing settings section grid pattern: left explanatory column, right control/content column. |
| Section title | Prefer `API Tokens` or `Developer API`; Obsidian may appear as a usage label, not the token type. |
| Token list | Compact rows showing token name, scope, created date, last used date, token preview if available, and revoke action. |
| Generate flow | Inline form or compact dialog with token name and scope. Show raw token exactly once after creation. |
| Obsidian guidance | Setup instructions should tell users to use a CallVault API token with the REST API/plugin, not an Obsidian-specific token. |
| Export zip | Existing one-click ZIP export can remain if still useful, but it should not force a separate token architecture. |

---

## Spacing Scale

Declared values must use Tailwind spacing already present in settings:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps inside buttons |
| sm | 8px | Row/content gaps |
| md | 16px | Form and card padding |
| lg | 24px | Section internal spacing |
| xl | 32px | Control group separation |
| 2xl | 48px | Settings section separation |

Exceptions: none.

---

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | Existing `text-sm` |
| Label | 12px | 600 | Existing uppercase section labels where already used |
| Heading | 14px | 800 | Existing `font-montserrat font-extrabold uppercase tracking-wide text-sm` settings headings |
| Token value | 12px | 500 | Monospace, wraps/truncates safely |

Do not introduce viewport-scaled typography.

---

## Color

Use existing semantic tokens only:

| Role | Value | Usage |
|------|-------|-------|
| Background | `background` | Page background |
| Surface | `card`, `muted/20` | Token rows, form shell, reveal box |
| Border | `border`, `border-border/60` | Row/card boundaries |
| Accent | `primary` | Primary generate/copy actions only |
| Destructive | `destructive` | Revoke confirmation action only |

No new palette, gradients, or decorative background elements.

---

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Generate API token` |
| Empty state heading | `No API tokens yet` |
| Empty state body | `Generate a token to connect Obsidian or another integration to the CallVault REST API.` |
| One-time reveal heading | `Copy your API token now` |
| One-time reveal body | `This token is shown once. Store it somewhere secure before closing this message.` |
| Error state | `Token action failed. Try again or refresh this page.` |
| Destructive confirmation | `Revoke API token? Revoking this token immediately blocks integrations that use it.` |

Avoid using `AI-powered` in UI copy.

---

## Interaction Contract

- Token generation must be explicit; no automatic token creation on page load.
- Raw token values are shown once after creation and never re-exposed from list views.
- Copy action should use a Remix copy icon plus text where space allows.
- Revoke action must require confirmation.
- Token source/type should not be exposed as confusing internal copy. User-facing copy should say `API token`.
- Obsidian setup text may say it uses a CallVault API token.
