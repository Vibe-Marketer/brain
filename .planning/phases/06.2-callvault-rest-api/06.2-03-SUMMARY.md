# Phase 06.2 Plan 03: Obsidian Token Cleanup Summary

**One-liner:** Deleted three dead Obsidian-token files, moved the export data-fetch utility into api-tokens.service.ts, and removed the unused obsidian-sync Edge Function.

---

## What Was Built

Phase 06.2 Plan 01 left three orphaned files (service, hook, component) that implemented a separate Obsidian-token credential universe. IntegrationsTab no longer referenced them. This plan removes those files entirely and eliminates the backend route that relied on `token_source = 'obsidian'` authentication.

The `fetchAllCallsForObsidianExport` function (used by `ApiTokensSection` for the one-click ZIP export) was moved from `obsidian-tokens.service.ts` into `api-tokens.service.ts` before deletion so the export button continues to work.

## Deviations from Plan

**[Rule 2 - Missing Critical Functionality] Import types moved inline**

`ApiTokensSection.tsx` imported `GeneratedApiToken` and `ApiToken` types via a separate `import type` from `api-tokens.service.ts` while also importing `fetchAllCallsForObsidianExport` from `obsidian-tokens.service.ts`. After moving the function, both imports were consolidated into a single `import` statement from `api-tokens.service.ts` using inline `type` qualifiers. No behavior change.

---

## Known Stubs

None. The `fetchAllCallsForObsidianExport` function is fully wired: it queries workspaces, workspace_entries, and recordings via the authenticated Supabase client — no separate token needed.
