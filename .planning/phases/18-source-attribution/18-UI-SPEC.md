# Phase 18 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui primitives already installed |
| Preset | `components.json`: default style, Vite, TSX, Tailwind v3, `baseColor: slate`, CSS variables, `@/` aliases |
| Component library | Radix-backed shadcn primitives already in `src/components/ui` |
| Icon library | Remix Icons only from `@remixicon/react`; shadcn CLI reports lucide, but repo rules override it |
| Font | Montserrat for section headings; Inter for body, controls, tables, labels, and metrics |

Use existing Admin Center surfaces only:

- Dashboard metrics live in `src/pages/admin/DashboardSection.tsx`.
- Ticket filter, source grouping, source summary, and table behavior live in `src/pages/admin/TicketsSection.tsx`.
- Source column rendering stays in `src/components/settings/TicketTable.tsx`.
- Ticket detail metadata may show source if useful, but this phase does not require a new dialog layout.
- Plain-English source labels live in `src/lib/ticket-display.ts` and must be reused everywhere.

No new route, top-level admin tab, design system, icon package, animation package, or third-party registry block.

## Source Labels

D-01 is locked. Operator-facing UI must never expose raw enum values such as `manual`, `sentry`, `nightly_qa`, `internal`, `unknown`, or `in_app_user`.

| Source value | Required operator label |
|--------------|-------------------------|
| `manual` | Reported by a person |
| `in_app_user` if introduced | Reported by a person |
| `sentry` | Found by Sentry |
| `nightly_qa` | Found by nightly QA |
| `internal` | Internal watchdog |
| `unknown` | Unknown source |
| null, empty, unrecognized | Unknown source |

The existing fallback that prettifies unknown values is not acceptable for this source surface. Source display must return `Unknown source` for unrecognized values so a future enum cannot leak as title-cased implementation text.

## Spacing Scale

Declared values, all multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, sort icon gaps, dense metric row separators |
| sm | 8px | Inline control gaps, source badge padding, compact row spacing |
| md | 16px | Default section spacing, filter row gaps, card internal rhythm |
| lg | 24px | Dashboard grid gaps, metric card padding via existing `Card` primitives |
| xl | 32px | Not used for new source controls unless inherited from existing card layout |
| 2xl | 48px | Empty-state vertical padding only |
| 3xl | 64px | Not used in this phase |

Exceptions:

- Existing Admin Center uses `space-y-4`, `space-y-6`, `gap-4`, `gap-6`, `p-3`, `p-4`, and `Card` default `p-6`; preserve that rhythm.
- Interactive controls must keep at least 44px effective touch target height on mobile.
- Table rows remain dense: `h-10 md:h-12`, no expanded card-like rows.

## Typography

Use exactly these roles for new source attribution UI:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Label | 12px (`text-xs`) | 500 | 1.4 |
| Heading | 14px (`text-sm`) | 800 Montserrat | 1.2 |
| Metric | 24px (`text-2xl`) | 700 | 1.2 |

Rules:

- Section headings use `font-montserrat font-extrabold uppercase tracking-wide text-sm`.
- Table headers remain uppercase Inter Medium at `text-xs` or current table classes.
- Source labels in selects, summaries, tables, and metrics use sentence case.
- Numbers use `tabular-nums`.
- Do not scale font size with viewport width.
- Do not introduce negative letter spacing.

## Color

Use semantic Tailwind tokens, not hardcoded hex values:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-card`, `text-foreground` | Admin content background, table body, primary text |
| Secondary (30%) | `bg-muted/30`, `border-border`, `text-muted-foreground` | Source summary strip, filter groups, helper text, dividers |
| Accent (10%) | `text-vibe-orange`, `bg-vibe-orange/10`, `border-vibe-orange/30`, focus ring | Active source filter/group, "needs attention" comparison, focus state only |
| Destructive | Existing destructive/status tokens only | No destructive action is introduced by this phase |

Accent reserved for:

- Active segmented/grouping state when grouping by source is toggled or selected.
- Dashboard/Tickets metric emphasis only when the metric means work needing attention.
- Focus rings through existing component behavior.
- Existing active Admin Center affordances.

Do not use vibe orange for ordinary body text, source labels, every interactive element, or decorative fills.

## Interaction Contract

### Tickets Source Filter

- Keep the existing Source select beside Severity.
- Replace option text with the required plain-English labels.
- Options, in order: `All sources`, `Reported by a person`, `Found by Sentry`, `Found by nightly QA`, `Internal watchdog`, `Unknown source`.
- Selecting a source resets pagination to page 1.
- Filtered empty state copy: `No tickets match these filters`.

### Tickets Source Grouping

Preferred contract:

- Add a compact grouping control near the source filter, not a new page.
- Control label: `Group by source`.
- Use a switch, checkbox, or compact segmented state consistent with current Admin Center controls.
- Default: off, preserving the current table.
- When on, group the already loaded ticket rows by source label, in this order: Reported by a person, Found by Sentry, Found by nightly QA, Internal watchdog, Unknown source.
- Each group header is a thin row or unframed section label, not a card. Header copy format: `{Source label} · {count}`.
- Groups with zero tickets in the current result set do not render in the table body.

Fallback contract if grouping would force a broad table rewrite:

- Keep grouping as a compact source summary strip above the table.
- Each source summary item acts as a one-click filter.
- This satisfies the operator scan goal without rebuilding the table.

### Tickets Source Summary

Render near source controls, above the table:

- Heading: `Source mix`.
- One compact item per source with volume, fix rate, and cycle time.
- Item copy format:
  - `{Source label}`
  - `{volume} tickets`
  - `{fixRate}% fixed`
  - `{cycleTime} avg cycle` or `No cycle time yet`
- Clicking a source item sets the source filter and page 1.
- The selected source item uses the same active treatment as existing selected controls: `bg-card text-foreground shadow-sm` or `bg-vibe-orange/10 border-vibe-orange/30` if a bordered item is used.

### Dashboard Per-Source Metrics

Add source metrics inside the existing Dashboard stats area:

- Preferred placement: a new `Card` in the dashboard grid or a source breakdown inside the existing Tickets card if it remains scannable.
- Title: `Tickets by Source`.
- Do not replace the existing "Need attention" and "Resolved" headline numbers.
- Render volume, fix rate, and average cycle time per source in compact rows.
- Row format: source label on the left; metrics on the right using tabular numbers.
- Cycle-time formatting:
  - `< 24 hours`: `N h`
  - `>= 24 hours`: `N d`
  - null/no resolved tickets: `No cycle time yet`
- Fix rate formatting: whole percentage, e.g. `67% fixed`; no decimals.

### Source Column

- Keep the existing SOURCE table column.
- Render `ticketSourceLabel(ticket.source)` only after it implements the locked label table.
- Do not add color-coded source badges unless the source column becomes hard to scan after grouping; plain text is preferred.
- If badges are used, use `StatusBadge` `default` or `outline` treatment only. Do not assign unique hue palettes per source.

### Ticket Detail

- If source is added to the detail dialog, place it in the metadata/status area as text: `Source: {Source label}`.
- Do not add source editing. Source is server-owned and not user-editable in this phase.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No new primary CTA. Keep existing `New Ticket`. |
| Source filter label | Source |
| Grouping control | Group by source |
| Summary heading | Source mix |
| Dashboard card title | Tickets by Source |
| Empty state heading | No tickets match these filters |
| Empty state body | Try a different source or severity. |
| Metrics unavailable | Source metrics failed to load. Retrying in the background. |
| Cycle time unavailable | No cycle time yet |
| Destructive confirmation | None; this phase adds no destructive action. |

Prohibited copy:

- No "AI-powered".
- No raw enum values.
- No jargon such as `in_app_user`, `nightly_qa`, `internal`, `manual`, `RPC`, or `enum` in operator-facing UI.
- No inflated explanatory copy; operators should scan counts and origin labels quickly.

## Accessibility

- Every filter/group control has a visible `Label` or clear `aria-label`.
- Source summary items that filter results are `<button type="button">`, not clickable divs.
- Source summary buttons expose selected state with `aria-pressed` or equivalent.
- Focus rings remain visible and use existing vibe-orange focus tokens.
- Text contrast must meet WCAG AA in light and dark mode.
- Source grouping must preserve keyboard row navigation and row click behavior.
- Source labels must not rely on color alone.
- Dashboard metric rows must remain readable at mobile widths; stack metrics under the source label if needed.

---

## Responsive Contract

- Desktop (`lg`): filters and source summary can sit in one horizontal band if text fits.
- Tablet (`md`): filters remain two columns or wrap; source summary uses a 2-column grid.
- Mobile (`<768px`): filters stack; source summary becomes a single-column list; table remains horizontally scrollable as today.
- Do not hide source metrics on mobile. If the table source column stays hidden at small widths, the summary/list must still expose source attribution.
- Long source labels must wrap rather than overflow.
