<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migration author -> production Postgres | Schema changes alter enum values, backfill ticket rows, and expose an RPC consumed by admin UI |
| browser/admin -> ticket_source_metrics RPC | Browser is untrusted; operational ticket metrics must be visible only to admins |
| historical ticket context -> source backfill | Existing JSONB context may be incomplete or attacker-influenced; backfill must be conservative |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Tampering | `ticket_source` enum migration | mitigate | Add values append-only in a standalone migration; never recreate/reorder existing enum values. |
| T-18-02 | Spoofing | legacy backfill predicates | mitigate | Only use explicit operational markers or null reporter system rows; never infer `in_app_user`; leave uncertain data as `unknown` per D-03. |
| T-18-03 | Information Disclosure | `ticket_source_metrics()` | mitigate | SECURITY DEFINER with pinned search_path, internal `public.has_role(auth.uid(), 'ADMIN')` guard, PUBLIC/anon revoked, and authenticated execute granted for the admin browser RPC path. |
| T-18-04 | Repudiation | source correction migration | mitigate | Use targeted SQL predicates that can be audited in migration history; do not perform broad opaque rewrites. |
| T-18-SC | Tampering | npm installs | accept | No package installs are planned; zero new npm packages per roadmap constraint. |
</threat_model>
