# Plan 30-04: Backfill orphan recordings rows for Fathom raw calls

<objective>
Insert a `recordings` row for every `fathom_raw_calls` row that has no matching
`recordings.legacy_recording_id` so the helper from Plan 30-01 can resolve the
canonical UUID instead of returning `null`. After this plan, the BUG-01 fix
from Plan 30-02 covers 100% of the user's Fathom-imported calls (1927 already
matched + 91 newly backfilled = 2018 total), not just the 1927 matched ones.

This unblocks Plan 30-03 — the integration tests need a fully consistent data
state so that the Folders column and Tag-with-AI flow work end-to-end on the
live test DB.
</objective>

<context>

## Why this is needed

Plan 30-02 audit (see `30-02-SUMMARY.md` Task 6) ran two SQL probes:

```sql
SELECT count(*) AS orphan_fathom_calls
FROM fathom_raw_calls f
LEFT JOIN recordings r ON r.legacy_recording_id = f.recording_id
WHERE r.id IS NULL;
-- 91 orphans (~4.5% of 2018 total)

SELECT count(*) FROM recordings
WHERE id::text !~ '^[0-9a-f]{8}-[0-9a-f]{4}-...';
-- 0 corrupt UUIDs
```

The 91 orphans span 2 users and a long time range (2025-11 → 2026-04). They
are Fathom calls that were fetched into `fathom_raw_calls` but never
sync-inserted into `recordings` — likely due to past sync-pipeline gaps that
have since been fixed by Phases 13–25 but never had a retroactive backfill.

User decision (locked 2026-05-11): write a one-shot migration to insert
`recordings` rows from the existing `fathom_raw_calls` data. Idempotent.

## Schema reference (verified against live DB on 2026-05-11)

| Table | Key columns | Type |
|-------|------------|------|
| `fathom_raw_calls` | `recording_id` (PK), `user_id`, `title`, `recording_start_time`, `recording_end_time`, `url`, `share_url`, `full_transcript`, `summary`, `auto_tags`, `meeting_fingerprint`, `source_platform`, `metadata`, `created_at`, `synced_at`, `canonical_recording_id` | bigint / text / jsonb |
| `recordings` | `id` (UUID PK), `legacy_recording_id` (bigint), `organization_id` (uuid NOT NULL), `owner_user_id` (uuid NOT NULL), `title` (text NOT NULL), `source_app`, `source_metadata`, `duration`, `recording_start_time`, `recording_end_time`, `created_at`, `synced_at` | uuid / various |
| Unique constraint | `recordings_organization_id_legacy_recording_id_key` = `UNIQUE (organization_id, legacy_recording_id)` | — |

### organization_id resolution rule

`fathom_raw_calls` does NOT have `organization_id` — it only has `user_id`.
Each affected user belongs to multiple orgs:

| user_id | orgs | orphan rows |
|---------|------|-------------|
| abb09c9b…b9818 | Personal (43a2ae24…), AI Simple (04714fb3…) | 4 |
| ef054159…ee6 | Business, GoVibey, AI Simple (04714fb3…) | 87 |

The rule (matches what existing recordings show — verified by a `count(*)` query):
**Backfill each orphan into the user's PRIMARY personal org** = the org where
that user has the most existing `source_app = 'fathom'` recordings.

| user_id | primary org id | primary org name | existing fathom recordings in that org |
|---------|---------------|------------------|---------------------------------------|
| abb09c9b…b9818 | 43a2ae24-927a-4ba6-aa17-5d0a23e58008 | Personal | 159 |
| ef054159…ee6 | 04714fb3-d42c-42ad-801a-a8a49df6d06f | AI Simple | 1207 |

Rationale: orphans were ingested by the same connector that fed the matched
1927 rows. The org that received the most matched rows is the org the orphans
"would have" landed in had the pipeline not faulted. This avoids creating new
recordings in business/secondary orgs where they don't belong.

## Task 1 — Create the migration file

**Files:** `supabase/migrations/<timestamp>_backfill_orphan_fathom_recordings.sql` (new)

**Naming convention** (per `supabase/CLAUDE.md`):
`YYYYMMDDHHMMSS_backfill_orphan_fathom_recordings.sql`

Use `supabase migration new backfill_orphan_fathom_recordings` to generate the
timestamped filename — do NOT hand-write the timestamp.

**Migration body:**

```sql
-- Migration: Backfill orphan fathom_raw_calls into recordings
-- Purpose: Insert missing `recordings` rows for the 91 fathom_raw_calls rows
--          that have no matching `recordings.legacy_recording_id`. Resolves the
--          last remaining surface of BUG-01 (Phase 30).
-- Author:  Claude (orchestrated by Andrew)
-- Date:    2026-05-11
-- Plan:    .planning/phases/30-uuid-legacy-id-root-cause-fix/30-04-PLAN.md
--
-- Idempotency: ON CONFLICT (organization_id, legacy_recording_id) DO NOTHING.
-- Safe to re-run; safe to apply after Phase 39 (Fathom mirror rebuild) which
-- might re-import these calls.

BEGIN;

-- Step 1: insert recordings rows for orphan fathom_raw_calls.
-- Resolve organization_id by picking the user's PRIMARY personal org —
-- the org where they have the most existing `source_app = 'fathom'`
-- recordings. See Plan 30-04 context for rationale.
WITH user_primary_org AS (
  SELECT owner_user_id, organization_id
  FROM (
    SELECT
      r.owner_user_id,
      r.organization_id,
      ROW_NUMBER() OVER (
        PARTITION BY r.owner_user_id
        ORDER BY count(*) DESC
      ) AS rn
    FROM recordings r
    WHERE r.source_app = 'fathom'
    GROUP BY r.owner_user_id, r.organization_id
  ) ranked
  WHERE rn = 1
),
orphans AS (
  SELECT f.*
  FROM fathom_raw_calls f
  LEFT JOIN recordings r ON r.legacy_recording_id = f.recording_id
  WHERE r.id IS NULL
)
INSERT INTO recordings (
  legacy_recording_id,
  organization_id,
  owner_user_id,
  title,
  audio_url,
  video_url,
  full_transcript,
  summary,
  global_tags,
  source_app,
  source_call_id,
  source_metadata,
  duration,
  recording_start_time,
  recording_end_time,
  created_at,
  synced_at
)
SELECT
  o.recording_id,
  upo.organization_id,
  o.user_id,
  COALESCE(NULLIF(TRIM(o.title), ''), 'Untitled Call'),
  o.url,
  o.share_url,
  o.full_transcript,
  o.summary,
  COALESCE(o.auto_tags, '{}'),
  COALESCE(o.source_platform, 'fathom'),
  o.recording_id::text,
  jsonb_build_object(
    'external_id', o.recording_id::text,
    'recorded_by_name', o.recorded_by_name,
    'recorded_by_email', o.recorded_by_email,
    'calendar_invitees', o.calendar_invitees,
    'meeting_fingerprint', o.meeting_fingerprint,
    'google_calendar_event_id', o.google_calendar_event_id,
    'google_drive_file_id', o.google_drive_file_id,
    'sentiment_cache', o.sentiment_cache,
    'original_metadata', o.metadata,
    'backfilled_by', 'phase-30-04',
    'backfilled_at', NOW()::text
  ),
  COALESCE(
    EXTRACT(EPOCH FROM (o.recording_end_time - o.recording_start_time))::INTEGER,
    0
  ),
  o.recording_start_time,
  o.recording_end_time,
  o.created_at,
  COALESCE(o.synced_at, NOW())
FROM orphans o
JOIN user_primary_org upo ON upo.owner_user_id = o.user_id
ON CONFLICT (organization_id, legacy_recording_id) DO NOTHING;

-- Step 2: link the new recordings back into fathom_raw_calls.canonical_recording_id
-- so existing query paths that join on that column also resolve cleanly.
UPDATE fathom_raw_calls f
SET canonical_recording_id = r.id
FROM recordings r
WHERE r.legacy_recording_id = f.recording_id
  AND f.canonical_recording_id IS NULL;

COMMIT;

-- ============================================================================
-- VERIFICATION (informational SELECTs — safe to run inside the transaction or after)
-- ============================================================================
-- After this migration, the orphan count MUST be 0.
-- Run this to verify:
--
--   SELECT count(*) AS remaining_orphans
--   FROM fathom_raw_calls f
--   LEFT JOIN recordings r ON r.legacy_recording_id = f.recording_id
--   WHERE r.id IS NULL;
--
-- Expected: 0
--
-- Sanity check on which org the orphans landed in:
--
--   SELECT r.organization_id, count(*) AS new_rec_count
--   FROM recordings r
--   WHERE r.source_metadata->>'backfilled_by' = 'phase-30-04'
--   GROUP BY r.organization_id;
--
-- Expected: rows in (43a2ae24-927a-4ba6-aa17-5d0a23e58008 = 4)
--                   (04714fb3-d42c-42ad-801a-a8a49df6d06f = 87)
```

## Task 3 — Verify the backfill

**Run via `mcp__postgres__query` (read-only):**

```sql
-- Probe 1: orphan count MUST be 0
SELECT count(*) AS remaining_orphans
FROM fathom_raw_calls f
LEFT JOIN recordings r ON r.legacy_recording_id = f.recording_id
WHERE r.id IS NULL;

-- Probe 2: backfilled rows landed in the correct orgs
SELECT r.organization_id, count(*) AS new_rec_count
FROM recordings r
WHERE r.source_metadata->>'backfilled_by' = 'phase-30-04'
GROUP BY r.organization_id
ORDER BY new_rec_count DESC;

-- Probe 3: every backfilled row has a non-null title (NOT NULL constraint on recordings.title)
SELECT count(*) AS rows_with_title
FROM recordings
WHERE source_metadata->>'backfilled_by' = 'phase-30-04'
  AND title IS NOT NULL AND length(title) > 0;
```

**Expected results:**
- Probe 1: `remaining_orphans = 0`
- Probe 2: 4 rows in `43a2ae24…`, 87 rows in `04714fb3…`
- Probe 3: 91 rows (every backfilled row has a title)

**Branch:**
- All 3 probes pass → continue to Plan 30-03 (integration tests).
- Probe 1 returns > 0 → STOP, file a follow-up bug. Some orphan didn't match
  the user_primary_org rule — likely the user has zero existing fathom
  recordings (edge case not covered in Plan 30-04 audit). Investigate before
  proceeding.

**Acceptance criteria:**
- All 3 probes return expected values.
- Results recorded in `30-04-SUMMARY.md` during execution.
