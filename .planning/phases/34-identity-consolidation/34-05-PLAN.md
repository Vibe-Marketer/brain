## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React client -> get_identity_evidence RPC | Any authenticated viewer can call it; it is redacted server-side so the client never receives the raw email |
| viewer without ownership -> a resolved speaker's evidence | Must see confidence + evidence text only, not the underlying email PII |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-05-01 | Information Disclosure | evidence popover leaking raw email to a non-owner viewer | mitigate | The UI reads ONLY get_identity_evidence, which returns (alias_type, confidence, evidence) and never `value` (Plan 02). The component is built to render those three fields only; there is no client path to identity_aliases.value. HIGH severity (IDENT-08's PII-minimization intent). |
| T-34-05-02 | Information Disclosure | fabricating/implying a resolution that did not happen | mitigate | The badge renders only when identity_id is truthy; unresolved speakers show nothing — no inferred/guessed confidence is ever displayed. |
| T-34-05-03 | Denial of Service | eager evidence fetch for every speaker on every render | mitigate | useIdentityEvidence is lazy (enabled only when the popover opens), so a call with N speakers fires zero evidence RPCs until a user explicitly asks. |
| T-34-05-SC | Tampering | npm/pip/cargo installs | accept | No package installs — Radix popover, Remix Icons, TanStack Query all already installed (34-RESEARCH.md Package Legitimacy Audit: N/A). |
