<objective>
Implement IDENT-02: resolution that spans email aliases, provider participant IDs, and display-name variants — and NEVER auto-links on name similarity alone. A pure matching module (`identity-resolver.ts`) does the deterministic work: an exact match on a verified email or a provider participant id links a `speakers`/`contacts`/`call_participants` row to an identity (high confidence); a display-name variant is recorded only as an unverified candidate that never, by itself, sets `identity_id`. A `resolve-identities` edge function wraps it, forward-only, mirroring this milestone's `resolve-events` shared-secret pattern.

Purpose: The single hardest guarantee in this phase is the negative one — never merging two different people because their names look alike. Isolating the matching logic in a pure, unit-tested module makes that guarantee provable (the negative test is the centerpiece), and keeps the resolver consistent with the milestone's established resolve-events architecture.
Output: A unit-proven resolver module + a deployable resolve-identities function (forward-only, verified/provider-id-only). Function deploy to prod is gated in Plan 07; wiring a continuous trigger/cron is an operational follow-on (the capability ships inert-until-invoked, exactly like resolve-events did).
</objective>
