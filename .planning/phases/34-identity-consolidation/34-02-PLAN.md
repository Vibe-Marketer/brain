## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated JWT -> identities RLS | A logged-in user (any org) querying identities — must see only identities they own or participate with |
| foreign-org JWT -> identities/identity_aliases | An Org-B user must read ZERO rows for an identity linked only to Org A's participants/contacts |
| any viewer -> get_identity_evidence | The RPC is callable by any authenticated user; it must never leak the raw email `value` |
| authenticated JWT -> identity_aliases | Raw `value` (email PII) — only the identity owner may SELECT directly |
| service_role -> identities/identity_aliases | Trusted; the OTP confirm function + resolver (Plans 03/04) write via service-role only |
