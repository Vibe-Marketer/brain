Per 35-VALIDATION.md Per-Task Verification Map — exactly these behaviors, adversarial:
- propagate: named chunk (speaker has resolved identity_id) + anonymous chunk from another recording of same event whose derived AbsoluteInterval genuinely overlaps → identity propagates.
- never.*display.name (adversarial negative): named chunk with a matching speaker_name STRING but identity_id=null → propagation MUST NOT fire (returns unresolved). Guards Pitfall 3.
- overlap-adversarial: two intervals that are CLOSE but do not actually overlap → MUST NOT propagate (proves overlap is really checked, not just "same event").
- collapse: labeled source shows one continuous speaker across an interval that an anonymous source split into Speaker-1/Speaker-2 → phantom collapses to the labeled identity.
- disagree (adversarial negative): two genuinely different speakers on the unlabeled side → MUST NOT be collapsed; stays unresolved.
- unresolved: chunk with no calendar/attendee/named-source corroboration → returns the literal-typed `resolved:false, identity_id:null` shape, never a guessed name.
