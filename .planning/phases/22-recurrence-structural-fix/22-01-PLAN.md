<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ticket context -> SQL rollup | Reporter/Sentry/QA-controlled ticket context feeds class-key extraction and metrics. |
| service role -> ticket_classes/tickets | Rollup RPC can write class rows and internal task tickets. |
| authenticated admin -> metrics RPC | Browser reads recurrence classes through an admin-only RPC. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Tampering | `rollup_ticket_classes()` class-key formation | mitigate | Normalize source/error/fingerprint parts in SQL and prefix fingerprint roots with normalized source; never trust a bare fingerprint. |
| T-22-02 | Information Disclosure | `ticket_classes` and `ticket_class_metrics()` | mitigate | Enable RLS, grant SELECT only to ADMIN via policy/RPC guard, revoke public/anon execution. |
| T-22-03 | Denial of Service | structural task creation | mitigate | Persist `structural_ticket_id` and check open statuses before insert so repeated rollups do not spam tasks. |
| T-22-04 | Elevation of Privilege | structural-fix task path | mitigate | Insert only `type='task'`, `source='internal'`, `status='escalated'`; no approval, merge, push, or auto-fix call exists in this RPC. |
| T-22-SC | Tampering | npm installs | mitigate | No packages are installed; verify `git diff -- package.json package-lock.json` is clean. |
</threat_model>
