<objective>
Harden `cloudflare/api-proxy/worker.ts` against XFF chain spoofing and redirect_to injection per ISC-39–43 (HIGH security gate):
1. Strip inbound `x-forwarded-for` from STRIP_REQUEST_HEADERS and rebuild fresh from CF-Connecting-IP only
2. Filter query params on `/auth/v1/oauth/authorize` routes — only allowlisted params forwarded
3. Add `x-forwarded-host` to STRIP_REQUEST_HEADERS

Purpose: The existing api-proxy Worker preserves inbound XFF headers, enabling attackers to spoof their IP for rate limit and IP allowlist bypass. The Worker also forwards url.search verbatim on auth routes, enabling redirect_to injection against Supabase Auth.

Output: Modified `cloudflare/api-proxy/worker.ts` with XFF hardening and auth route query param filtering.
</objective>

<threat_model>
**ASVS Level:** L1

**Threats addressed by this plan:**
- [T-06.1-XFF-01]: Tampering — XFF chain spoofing. Attacker sets X-Forwarded-For: &lt;trusted-IP&gt; to bypass rate limits or IP allowlists. Mitigation: Worker strips inbound x-forwarded-for from STRIP_REQUEST_HEADERS; rebuilds fresh from CF-Connecting-IP (ISC-39–40).
- [T-06.1-AUTH-01]: Tampering — redirect_to injection on auth routes. Attacker appends redirect_to or other malicious params to /auth/v1/oauth/authorize URL forwarded by the Worker. Mitigation: only allowlisted OAuth params (client_id, redirect_uri, response_type, code_challenge, code_challenge_method, state, scope) forwarded on auth routes (ISC-41–42).
- [T-06.1-HOST-01]: Tampering — x-forwarded-host header injection. Attacker injects x-forwarded-host to manipulate origin resolution. Mitigation: x-forwarded-host added to STRIP_REQUEST_HEADERS (ISC-43).

**Residual risks:** None — changes are in the Cloudflare Worker which processes all requests before they reach Supabase Edge Functions.

**Block condition:** Any HIGH severity threat not mitigated = executor must stop and surface to operator.
</threat_model>
