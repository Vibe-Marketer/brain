# Phase 06.1 — UI Design Contract

## Component Inventory

These are the exact components used in the `oauth-auth-screen` plan additions to `OAuthConsentPage.tsx`. No new components are introduced.

### 1. First-Time Connection Badge

**When shown:** When the OAuth `client_id` has no existing approved grant in the `mcp_oauth_grants` table for this user (i.e., this is the first time this client is requesting authorization).

**Component:** `Badge` from `@/components/ui/badge` with inline className override (the existing `badgeVariants` does not have an amber variant — use `className` override directly).

**Exact className:**
```tsx
<Badge className="border-amber-400 text-amber-700 bg-amber-50 gap-1.5">
  <RiErrorWarningLine className="h-3 w-3" aria-hidden="true" />
  First-time connection
</Badge>
```

**Placement:** Directly below the app name heading in `CardHeader`, before `<p>wants to access your CallVault account</p>`. It sits inside the `space-y-1` div alongside the h2 and subtitle.

**Exact placement in CardHeader `space-y-1` div:**
```tsx
<div className="space-y-1">
  <p className="text-xs font-inter font-medium text-muted-foreground uppercase tracking-wider">
    Authorization Request
  </p>
  <h2 className="font-montserrat font-extrabold text-xl">
    <span className="text-foreground">{appName}</span>
  </h2>
  {/* NEW: first-time badge — conditional */}
  {isFirstTimeClient && (
    <div className="flex justify-center pt-1">
      <Badge className="border-amber-400 text-amber-700 bg-amber-50 gap-1.5">
        <RiErrorWarningLine className="h-3 w-3" aria-hidden="true" />
        First-time connection
      </Badge>
    </div>
  )}
  <p className="text-sm text-muted-foreground font-inter font-light">
    wants to access your CallVault account
  </p>
</div>
```

**Interaction:** Display-only. No click handler. No hover state beyond the base Badge focus ring.

**Accessibility:** `RiErrorWarningLine` has `aria-hidden="true"` — the badge text provides the full semantic meaning.

### 2. Client ID Display

**When shown:** Always, on the consent screen. Never omit — CONTEXT.md D-15 forbids using `client_name` as the only identifier.

**Component:** `<span>` inside the existing `bg-muted/50` section panel, new sub-section after the permissions list or as a new `bg-muted/50` block.

**Display format:** Truncate UUID to first 8 chars + `…` + last 4 chars.
- Example: `a1b2c3d4-e5f6-7890-abcd-ef1234567890` → `a1b2c3d4…7890`
- Implementation: `clientId.slice(0, 8) + '…' + clientId.slice(-4)` where `clientId` is `authDetails?.client?.id ?? authDetails?.client_id`

**Exact element:**
```tsx
<div className="bg-muted/50 rounded-lg p-4 space-y-2">
  <p className="text-xs font-inter font-medium text-muted-foreground uppercase tracking-wide">
    Client Details
  </p>
  <div className="flex items-center gap-2">
    <RiShieldCheckLine className="h-4 w-4 text-muted-foreground flex-shrink-0" aria-hidden="true" />
    <div className="space-y-0.5">
      <p className="text-xs text-muted-foreground font-inter font-light">Client ID</p>
      <span className="font-mono text-xs text-foreground">
        {clientId ? `${clientId.slice(0, 8)}…${clientId.slice(-4)}` : 'Unknown'}
      </span>
    </div>
  </div>
</div>
```

**Placement:** New `bg-muted/50` block inserted after the permissions section, before the organization picker. Follows the same visual pattern as existing `bg-muted/50 rounded-lg p-4` blocks.

**Accessibility:** `RiShieldCheckLine` has `aria-hidden="true"`. The `font-mono text-xs` span is read aloud as plain text by screen readers — no additional ARIA needed.

### 3. Redirect Domain Display

**When shown:** Always, on the consent screen. Show only scheme + host from `authDetails?.redirect_uri` — never the full path.

**Format:** `new URL(redirectUri).origin` (e.g., `https://claude.ai`). If URL parsing fails, show the raw URI.

**Exact element (placed inside the Client Details block or as its own line):**
```tsx
<div className="flex items-center gap-2 mt-1.5">
  <RiShieldCheckLine className="h-4 w-4 text-muted-foreground flex-shrink-0" aria-hidden="true" />
  <div className="space-y-0.5">
    <p className="text-xs text-muted-foreground font-inter font-light">Redirect destination</p>
    <span className="text-xs font-inter text-foreground">
      {redirectDomain}
    </span>
  </div>
</div>
```

Where `redirectDomain` is computed as:
```ts
let redirectDomain = authDetails?.redirect_uri ?? '';
try { redirectDomain = new URL(redirectDomain).origin; } catch { /* use raw */ }
```

**Accessibility:** Decorative shield icon is `aria-hidden="true"`. Domain text is plain readable text.

### 4. Advisory Text

**When shown:** Always, on the consent screen. Below the redirect domain display.

**Exact copy:** "Only approve if you initiated this connection from your AI client."

**Exact element:**
```tsx
<p className="text-muted-foreground text-sm font-inter font-light">
  Only approve if you initiated this connection from your AI client.
</p>
```

**Placement:** Directly below the Client Details block (client ID + redirect domain), above the organization picker. As a standalone paragraph, not inside a `bg-muted/50` panel.

**Accessibility:** Plain paragraph. No icon. Screen reader reads naturally.

## Interaction Contract

### First-Time Detection Logic

The `isFirstTimeClient` flag is derived from the existing grant state. The consent page already has access to the authorization details — add a check:

```ts
// After fetchAuthorizationDetails resolves:
// isFirstTimeClient = true if no existing grant record exists for this client_id + userId combo
// This is a read from the mcp_oauth_grants table via a new hook or inline query
// If the check fails/errors, default to isFirstTimeClient = false (fail safe — do not block flow)
```

**Fail-safe rule:** If the first-time check cannot be completed (network error, missing data), render without the badge. Never block the consent flow.

### State Machine (no changes to existing states)

The additions affect only the `consent` page state. All new elements are display-only. No new states introduced.

| Element | Loading state | Error state | Success state |
|---------|--------------|-------------|---------------|
| First-time badge | Hidden (omit) | Hidden (fail safe) | Shown conditionally |
| Client ID | "Unknown" fallback | "Unknown" fallback | Truncated UUID |
| Redirect domain | Raw URI fallback | Raw URI fallback | Parsed origin |
| Advisory text | Always shown | Always shown | Always shown |

### No New Interactive Elements

All additions are read-only display elements. No new buttons, inputs, selects, or checkboxes. The existing `Button` and `Select` components for approve/deny/org-picker are unchanged.
