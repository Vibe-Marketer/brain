# Phase 06.1 Plan sec-jwt-fix: JWT Grant Pivot Fix Summary

Remove `readClientIdFromJwt()` from MCP auth — client_id now sourced exclusively from cryptographically-verified `jwtUser.app_metadata`.

## What Was Built

Closed a JWT grant scope pivoting vulnerability in `supabase/functions/mcp-server/auth.ts`.

Before this fix, `readClientIdFromJwt()` decoded the raw JWT payload using `atob()` without verifying the signature. An attacker who could forge a JWT with an arbitrary `client_id` claim could pivot to a different client's grant row in `mcp_oauth_client_grants`, gaining that client's org/workspace scope and `enabled_categories`.

After this fix, `client_id` is extracted exclusively from `jwtUser.app_metadata` — the user object returned by `authClient.auth.getUser(rawToken)`, which performs cryptographic JWT signature verification before returning any claims.
