# Phase 06.1 Plan sec-dcr-phishing: OAuthConsentPage Security Fields Summary

**One-liner:** Added DCR phishing-detection fields (truncated client_id UUID, first-time badge, redirect domain, advisory text) to OAuthConsentPage with 5-case TDD coverage.

## What Was Built

Task 1 implemented four security fields in `src/pages/OAuthConsentPage.tsx` per ISC-13–19 and the UI-SPEC.md layout contract:

1. **Truncated client_id UUID** — `a1b2c3d4…7890` format, always shown in Client Details block. Not attacker-controlled (UUID vs. client_name).
2. **First-time connection badge** — amber badge in CardHeader, conditional on `isFirstTimeClient = true`. Query: `mcp_oauth_client_grants WHERE user_id = user.id AND client_id = clientId AND revoked_at IS NULL`. If count === 0 and no error → show badge. Fail-safe: errors leave badge hidden.
3. **Redirect destination domain** — origin only (`https://claude.ai` not `/oauth/callback`), shown in Client Details block.
4. **Advisory text** — "Only approve if you initiated this connection from your AI client." — always shown.

Workspace param guard (ISC-35–38) was already present via `workspaces.find(ws => ws.id === requestedWorkspaceId)` with `if (!selectedOrgId) return` guard — confirmed active, added ISC-36 comment.
