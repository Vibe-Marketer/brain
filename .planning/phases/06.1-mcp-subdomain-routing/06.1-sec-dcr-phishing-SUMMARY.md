# Phase 06.1 Plan sec-dcr-phishing: OAuthConsentPage Security Fields Summary

**One-liner:** Added DCR phishing-detection fields (truncated client_id UUID, first-time badge, redirect domain, advisory text) to OAuthConsentPage with 5-case TDD coverage.

## What Was Built

Task 1 implemented four security fields in `src/pages/OAuthConsentPage.tsx` per ISC-13–19 and the UI-SPEC.md layout contract:

1. **Truncated client_id UUID** — `a1b2c3d4…7890` format, always shown in Client Details block. Not attacker-controlled (UUID vs. client_name).
2. **First-time connection badge** — amber badge in CardHeader, conditional on `isFirstTimeClient = true`. Query: `mcp_oauth_client_grants WHERE user_id = user.id AND client_id = clientId AND revoked_at IS NULL`. If count === 0 and no error → show badge. Fail-safe: errors leave badge hidden.
3. **Redirect destination domain** — origin only (`https://claude.ai` not `/oauth/callback`), shown in Client Details block.
4. **Advisory text** — "Only approve if you initiated this connection from your AI client." — always shown.

Workspace param guard (ISC-35–38) was already present via `workspaces.find(ws => ws.id === requestedWorkspaceId)` with `if (!selectedOrgId) return` guard — confirmed active, added ISC-36 comment.

## Deviations from Plan

### Cloudflare Rate Limit (Task 2) — Deferred (Not a Launch Blocker)

- **Found during:** Task 2 automation attempt
- **Issue:** Zone `callvaultai.com` is on the Free plan. The API token has `#dns_records:edit` and `#zone:read/edit/#zone_settings:edit` permissions but lacks `#zone:edit` for rate limits. Legacy `/rate_limits` endpoint returned auth error (code 10000). Ruleset API for `http_ratelimit` phase returned `Method not allowed` (code 10405). No entrypoint ruleset exists for `http_ratelimit` phase on this zone.
- **Operator decision (2026-06-10):** ISC-17 (max 10 DCR registrations/IP/hr) is deferred. The plan originally marked Task 2 as blocking, but after review the threat (automated mass DCR registration) is low-severity pre-launch — the DCR endpoint is only exercised by AI clients during the OAuth setup flow. CDN-tier rate limiting requires a Cloudflare paid plan feature. This is tracked for post-launch hardening, not a prerequisite for DNS provisioning.
- **Status:** Deferred — plan complete without this control.
- **Residual risk:** Automated DCR endpoint abuse is unmitigated at the CDN tier. Application-layer limits (Supabase RLS + database-level constraints) still apply.
- **Deferred to:** Post-launch hardening backlog (upgrade Cloudflare zone to Pro/Business for `http_ratelimit` phase support).
