# 06.1-12 Summary: MCP Subdomain Worker Routing

## Implemented

- Replaced the placeholder `callvault-mcp-subdomain` Worker with live routing for org and org-workspace subdomains.
- Expanded the Cloudflare route to `*.callvaultai.com/*` so `/mcp`, `/mcp-register`, `/auth/v1/*`, and `/.well-known/*` all reach the Worker.
- Added reserved-host passthrough for `api.callvaultai.com` and `mcp.callvaultai.com` because the wildcard route also matches those public surfaces.
- Added authoritative `x-callvault-org-slug`, optional `x-callvault-workspace-slug`, `x-callvault-scope`, `x-callvault-host`, and internal-secret forwarding while stripping inbound `x-callvault-*` headers first.
- Updated MCP protocol and OAuth metadata host resolution to accept controlled CallVault subdomains while still falling back for unrecognized hosts.
- Added MCP auth subdomain audience enforcement:
  - missing org slug keeps legacy behavior;
  - unknown org slug returns `404 {"error":"org_not_found"}`;
  - wrong org token returns `403 {"error":"token_org_mismatch"}`;
  - bad workspace slug or mismatched workspace token returns `403 {"error":"token_workspace_mismatch"}`;
  - org tokens on workspace subdomains are narrowed to the resolved workspace.

## Deviation

- The original plan said only `mcp-subdomain-worker` needed routing, but the wildcard Cloudflare route also catches `api.callvaultai.com` and `mcp.callvaultai.com`. The Worker therefore includes reserved-host passthrough so existing REST and legacy MCP URLs remain live.
- `cloudflare/api-proxy/worker.ts` had already been updated in the preceding 06.1-12 continuation to inject `CALLVAULT_INTERNAL_SECRET`; otherwise legacy API/MCP paths could not reach Edge Functions after the internal secret gate.
- `wrangler deploy` had to run from the Worker directory so Wrangler used the authenticated OAuth profile rather than the limited repo-root `.env` token.
