# Phase 06.1 Plan sec-worker-headers: Worker Header Hardening Summary

XFF chain spoofing prevention and OAuth redirect_to injection filtering in Cloudflare Worker via four targeted changes to `cloudflare/api-proxy/worker.ts`.

## What Was Built

Four security hardening changes applied to `cloudflare/api-proxy/worker.ts`:

**ISC-39/43 — Header stripping:**
Added `"x-forwarded-for"` and `"x-forwarded-host"` to `STRIP_REQUEST_HEADERS`. Previously only CF-internal headers were stripped; inbound XFF and x-forwarded-host from clients were passed through unchanged.

**ISC-40 — Fresh XFF from CF-Connecting-IP:**
After the strip loop, the worker now sets `x-forwarded-for` fresh from `request.headers.get("CF-Connecting-IP")`. Previously the code appended to the existing XFF chain (attacker-controlled); now the upstream always sees exactly one value: the IP Cloudflare verified. The variable capture (`realIp`) happens before the strip loop so CF-Connecting-IP is read before it gets deleted.

**ISC-41/42 — Auth route param allowlist:**
Added `OAUTH_ALLOWLISTED_PARAMS` constant and filtering logic in the fetch handler. When `url.pathname === "/auth/v1/oauth/authorize"`, the forwarded target URL is rebuilt with only allowlisted params (`client_id`, `redirect_uri`, `response_type`, `code_challenge`, `code_challenge_method`, `state`, `scope`). Any other params — including `redirect_to` — are silently dropped.

**ISC-123 — Deprecation header:**
Added `isDeprecatedMcpRoute()` helper function. Responses from `mcp.callvaultai.com` (all paths) and `api.callvaultai.com/mcp` and `/mcp/*` routes carry `Deprecation: true` to signal legacy endpoint status to clients.
