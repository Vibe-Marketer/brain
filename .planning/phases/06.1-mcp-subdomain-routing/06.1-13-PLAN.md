<objective>
Update `OAuthConsentPage.tsx` to handle the subdomain-origin OAuth flow introduced by the new Cloudflare Worker.

When an OAuth flow originates from `orgslug.callvaultai.com/mcp`, the Worker injects `x-callvault-org-slug` into every request. The OAuth authorization flow uses the `resource` parameter (RFC 8707) set to the subdomain URL. This plan:

1. Teaches the consent page to detect the subdomain origin from `authDetails` (via `resource` field or `redirect_uri` origin) and display the subdomain URL as the connection URL — the pre-scoped variant skips the org picker and locks the grant to the resolved org.
2. Verifies that `auth.ts` already has slug resolution and `token_org_mismatch` enforcement from the worker-routing plan (Wave 4 dependency). This plan does NOT re-implement auth.ts slug logic — it reads the SUMMARY from worker-routing to confirm the implementation is already in place and adds unit tests.

Note: `supabase/functions/mcp-server/auth.ts` is NOT in `files_modified` for this plan. The worker-routing plan (06.1-12-PLAN.md) is the exclusive owner of auth.ts slug resolution logic (ISC-82–89). This plan only reads auth.ts to verify it and adds tests.

Purpose: Without this, a token issued via `acmecorp.callvaultai.com/mcp` flow is identical to one from `mcp.callvaultai.com` — no org constraint embedded. This plan closes that gap on the consent page side.

Output:
- Modified `src/pages/OAuthConsentPage.tsx` with pre-scoped consent variant (orgSlug detection + subdomain URL display)
- Unit tests in `src/test/OAuthConsentPage.test.tsx` for subdomain pre-scoped behavior (extend the test file created by sec-dcr-phishing)
- Verified (not re-implemented) auth.ts slug enforcement from worker-routing
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cloudflare Worker → Supabase Edge Function | x-callvault-org-slug is injected by the Worker; the Edge Function trusts this header only because the Worker strips inbound x-callvault-* headers before re-injecting (ISC-5, sec-worker-bypass plan). If the internal secret is absent, no slug header is trusted. |
| Browser → Supabase OAuth server | authDetails returned by supabase.auth.oauth.getAuthorizationDetails is server-validated; the consent page reads it but never trusts client-supplied slug values for authorization decisions |
| Consent page → handleApprove | selectedOrgId is resolved from slug lookup against orgs the authenticated user belongs to — org membership is enforced by RLS on the organizations/org_members tables |
