# Plan 38-04: Cross-Org Cache Audit + OAuth Token Isolation Audit

## Objective

Confirm via dev-browser and code audit that:
1. Switching organizations clears any cached call/folder/tag data from the previous org (SEC-03C).
2. The frontend never receives raw OAuth provider tokens (Google, Fathom, Zoom); only the Supabase JWT is in client memory (SEC-03D).

Document findings in two security audit documents. Add `orgId` to TanStack Query keys where missing so a future regression can't reintroduce the leak.

Augment cross-org cache clearing. The current `src/contexts/AuthContext.tsx` clears the cache on `SIGNED_OUT` and on account-switch `SIGNED_IN` (lines 40-43, 58-62). But it does NOT clear the cache when the user switches **organizations** within the same account.

Add an `useEffect` somewhere appropriate (or a Zustand subscription) that clears the queryClient whenever `useOrgContextStore`'s `activeOrgId` changes. The cleanest place is `src/contexts/AuthContext.tsx` — extend the existing provider OR create a small `OrgCacheBoundary` component that subscribes to the store and calls `queryClient.clear()` on org change.

Proposed minimal patch — add to `src/contexts/AuthContext.tsx` inside the `AuthProvider`:

```typescript
// Clear TanStack Query cache whenever the active organization changes so
// org-A data never bleeds into the next org-B view. The existing query keys
// also include orgId (Plan 38-04 T01) for defense-in-depth, but a full
// queryClient.clear() guarantees no stale entry survives the switch.
useEffect(() => {
  const prevOrgRef = { current: useOrgContextStore.getState().activeOrgId };
  const unsubscribe = useOrgContextStore.subscribe((state) => {
    const newOrgId = state.activeOrgId;
    if (prevOrgRef.current !== null && prevOrgRef.current !== newOrgId) {
      logger.debug('[AuthContext] Active org changed — clearing query cache');
      queryClient.clear();
    }
    prevOrgRef.current = newOrgId;
  });
  return unsubscribe;
}, [queryClient]);
```

Place this useEffect alongside the existing `useEffect` that handles auth state. Import `useOrgContextStore` (already imported at the top — line 7).

After the edit, run `npm run type-check` and `npm run build`.

Step 2: Classify each hit:
- `session.access_token` — Supabase JWT, ALLOWED per SEC-03D acceptance ("only Supabase JWT is in client memory"). Used for `Authorization: Bearer` headers when calling edge functions. Examples: `BillingTab.tsx:144`, `UpgradeButton.tsx:73`, `useTeamHierarchy.ts:115`, `useAiGate.ts:82`, `useSharing.ts:243`, `usePolarCustomer.ts:97`.
- `oauth_access_token` / `google_oauth_access_token` / `zoom_oauth_access_token` — These are FIELD NAMES on `user_settings`. If the frontend `.select()`s these field names, the raw provider token IS pulled to the client. **This IS a leak**, even if the frontend only uses `!!settings?.oauth_access_token` for a boolean truthiness check.
- `oauth_refresh_token` / `zoom_oauth_refresh_token` — Same concern.

Step 3: For each `oauth_access_token` / `oauth_refresh_token` reference in `.select(...)` queries, refactor:
- **Option A (preferred):** Change `.select('oauth_access_token')` to `.select('oauth_token_expires')` — a boolean truthiness check on `oauth_token_expires` (or a dedicated `has_oauth` column) achieves the same UI signal without pulling the raw token to the client.
- **Option B (if no alternative column exists):** Add a server-side `has_oauth_token` boolean to the relevant select, returned by a Supabase view OR a database function. Lift the truthiness check to that.
- **Option C (acceptable interim):** If the existing column is the only source of truth, document this as a known limitation: the token IS pulled to the client but only its existence is checked. The risk is low because the column is RLS-protected to the owning user.

Hits to audit (from 2026-05-12 grep):
1. `src/components/settings/IntegrationsTab.tsx:53` — `.select("fathom_api_key, webhook_secret, oauth_access_token")`. `setHasOAuth(!!settings?.oauth_access_token)` at line 57. **Option A available:** select `oauth_token_expires` instead. If that's null, treat as no OAuth.
