## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → claim_organization_domain RPC | The only mutation surface here; authority re-checked server-side (Plan 01), UI gating is convenience only |
| rendered conflict error → user | Must not become a cross-org identity disclosure channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-10 | Information Disclosure | domain-claim conflict UI | mitigate | The conflict branch renders a fixed literal string, never interpolating an org name/id; the backend (Plan 01) already returns a name-free CONFLICT code, so the UI has nothing to leak even by mistake. |
| T-36-11 | Elevation of Privilege | client-side canManage gating | accept | canManage only hides controls; the real authority is is_organization_admin_or_owner inside the RPC (Plan 01). A user bypassing the UI gate still hits FORBIDDEN server-side. |
| T-36-12 | Denial of Service | N badges each firing a domains query | mitigate | Lazy fetch (enabled: open && !!id) so badges do not fan out N queries on mount, mirroring the IdentityEvidenceBadge rationale. |
</threat_model>
