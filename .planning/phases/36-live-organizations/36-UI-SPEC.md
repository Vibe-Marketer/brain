# Phase 36 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope covered by this contract** (per 36-CONTEXT.md "UI Surface"):
1. **Organization Identity** section — new section inside the existing `OrganizationsTab.tsx` settings surface (aliases + domain claim, self-serve, org admin/owner only).
2. **Verified-domain badge** — small on-demand affordance next to the organization name.
3. **Admin merge-duplicates + unclaim tool** — new internal-only section in the Admin Center (`/admin`), mirroring the existing `UsersSection.tsx` pattern.

Out of this contract's scope (schema/RLS/backend-only, no distinct UI state): exact column naming, RLS helper structure, dual-membership role resolution on merge — all explicitly deferred to plan-phase per 36-CONTEXT.md "Claude's Discretion." This UI-SPEC resolves the one CONTEXT.md discretion item that IS a UI decision: **the admin/service-role unclaim action gets a real UI affordance this phase** (see Admin Center row below), not DB-only — reasoning under UI Considerations.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks (matches `AccountTab.tsx`'s `mb-12` top separator) |
| 3xl | 64px | Page-level spacing (matches `AccountTab.tsx`'s `my-16` between settings sections) |

Exceptions: **none at the token level.** This phase reuses existing shadcn primitives (Card, Dialog, Table, Popover, Badge, Input, Select) whose internal spacing is already locked by the design system; new layout composition (section headers, alias/domain row lists, admin table) follows the standard scale above. One layout-specific rule is introduced for list containers — aliases/domains lists scroll past 8 visible rows via `max-h-64 overflow-y-auto` — this is a UI-polish decision without existing codebase precedent to point to, so it is flagged as a `backstop` item under UI Considerations rather than declared as a hard token exception.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 regular | 1.5 |
| Label / metadata | 12px (`text-xs`) | 400 regular | 1.4 |

3 distinct sizes declared (10/12/14 — 14 reused for two different roles/treatments), satisfying the 3-4 size budget. **Weight note:** 400 (regular) and 600 (semibold) are the two weights this phase newly applies to body/label content. The 800 (extrabold) heading weight is an **inherited, pre-existing, locked pattern** (`font-montserrat font-extrabold uppercase tracking-wide text-sm`, verbatim from `AccountTab.tsx` / `OrganizationsTab.tsx` / `UsersSection.tsx` section headers) — it is reused unchanged, not a new typography decision introduced by this phase, so it does not count against the 2-weight new-decision budget.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-card` — `#FFFFFF` light / `#212121` dark | Settings card surfaces, admin organizations table background |
| Secondary (30%) | `bg-muted` `#F2F2F2`/`#292929`; `border-border` `#E6E6E6`/`#3B3B3B` | Row dividers, table header background (`bg-muted/50`), hover states, expanded-domain-row background |
| Accent (10%) | `text-vibe-orange` / `bg-vibe-orange` — `#FF8800`, theme-invariant | See reserved-for list below |
| Destructive | `text-destructive` / `bg-destructive` (red) | Unclaim-domain confirm button, Merge-organizations confirm button, domain-claim-conflict error text — mirrors `variant="destructive"` in `DeleteOrganizationDialog.tsx` |

Accent reserved for — **exactly two surfaces, both automatic/inherited, zero new orange decisions this phase:**
1. Input/select focus rings on the new domain-claim and alias-add fields (global `--btn-focus-ring` behavior, automatic — not a per-phase style choice).
2. The Admin Center's new "Organizations" nav-category icon + label + left-edge pill when that category is active (inherited 4-layer `SidebarNav`/`AdminCategoryPane` active-state pattern — automatic once the category is registered, not a new visual decision).

**Explicitly NOT accent:** "Add alias," "Claim domain," "Merge organizations," and "Unclaim domain" all use `variant="hollow"` — matching `AccountTab.tsx`'s "Add email" precedent (a secondary settings-section action, not a page-level wayfinding CTA like "IMPORT" or "Create Folder"). The verified-domain badge icon itself uses `text-muted-foreground` (see below), not orange, matching `IdentityEvidenceBadge.tsx`'s icon treatment exactly.

## Implementation Pointers (non-template, for planner/executor convenience)

Concrete file/component recommendations, traced to exact existing precedents:

| New file | Mirrors | Purpose |
|----------|---------|---------|
| `src/components/settings/OrganizationIdentitySection.tsx` | `AccountTab.tsx`'s section pattern (h2 + description + content grid) | Aliases + domain claim, rendered inside `OrganizationsTab.tsx`'s existing per-org `<Card>`, before `<WorkspaceManagement>` |
| `src/components/shared/VerifiedDomainBadge.tsx` | `IdentityEvidenceBadge.tsx` (near-verbatim structure: `Popover` + icon-button trigger, `text-muted-foreground`, lazy-fetch on open) | Placed in the new section's `CardTitle`/heading, next to the org name. | `src/pages/admin/OrganizationsSection.tsx` | `UsersSection.tsx` (search/filter header + table + empty/loading/error states) | Registered in `AdminCategoryPane.tsx`'s `ADMIN_CATEGORIES` (new id `"organizations"`, icon `RiBuilding4Line`) and `AdminCenter.tsx`'s `renderSection()` switch + `VALID_SECTIONS` |
| `src/components/dialogs/MergeOrganizationsDialog.tsx` | `DeleteOrganizationDialog.tsx` (type-to-confirm, `variant="destructive"` submit) | Opened from an admin org row's "Merge into…" action |
| `src/components/dialogs/UnclaimDomainDialog.tsx` | `DeleteOrganizationDialog.tsx` (lighter — no type-to-confirm, single confirm click) | Opened from an admin org row's expanded domain list, per-domain "Unclaim" action |

**Admin-tool row interaction:** clicking an admin org-table row expands it inline (Radix `Collapsible`, matching `WorkspaceSidebarPane.tsx`'s established usage) to reveal that org's full domain/alias list with per-domain "Unclaim" buttons; a row-level "Merge into…" button opens `MergeOrganizationsDialog` with that row pre-selected as the losing org. This resolves 36-CONTEXT.md's open discretion point ("Whether the admin/service-role unclaim action gets a UI affordance now or stays DB-only this phase") in favor of **shipping a minimal UI affordance**, colocated with the merge tool in the same new Admin Center section, rather than DB-only — both actions are reversible, admin-gated, and low-frequency, so one small internal table earns its keep over requiring raw SQL for what will likely be a recurring correction (an org mistakenly claiming, or needing to release, a domain).

**Claimable-domain sourcing:** the domain-claim control's candidate list should derive client-side from the current user's own `useIdentityAliases()` verified emails (Phase 34, already wired into `AccountTab.tsx`) by extracting the substring after `@` — no new "list my claimable domains" backend endpoint is needed purely for the UI to function. If the user has zero verified emails, the claim control shows the "no verified email" error copy immediately, pointing to Account settings.
