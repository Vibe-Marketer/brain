<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → edge function | Untrusted JWT + body; the function verifies the JWT and independently checks has_role before any privileged work |
| edge function → service-role RPC | The function is the ONLY sanctioned caller of the REVOKE-EXECUTE'd RPCs; it must pass the verified caller id, never a body-supplied one |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-13 | Elevation of Privilege | merge/unclaim authorization | mitigate | has_role(authResult.userId,'ADMIN') gate (NOT org-membership — Pitfall 5); the RPC is unreachable by any client role (REVOKE EXECUTE, Plan 02), so the edge function is the sole path and it re-checks admin. |
| T-36-14 | Spoofing / Tampering | p_admin_user_id parameter | mitigate | The function always passes authResult.userId (JWT-verified) as p_admin_user_id; the body carries only org/domain ids, never an actor id. The RPC also re-validates has_role(p_admin_user_id) as defense in depth. |
| T-36-15 | Information Disclosure | error responses | mitigate | Raw Postgres/RPC errors are console.error'd server-side; the client gets a short generic message — no conflicting-org identity, no internal detail. |
| T-36-16 | Tampering | malformed payload | mitigate | Zod safeParse on uuid-shaped fields; 400 on invalid input before any DB call. |
</threat_model>
