Ship the internal, platform-admin-only Admin Center surface for merging duplicate orgs and unclaiming domains (ORG-03), colocating both reversible operations in one new "Organizations" section that mirrors the existing UsersSection pattern.

Output: an admin org table with inline row-expand, the merge + unclaim dialogs, the admin service/hook layer, and Admin Center registration.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser → edge functions | Admin Center is ADMIN-scoped; the real authority is the edge functions' has_role gate (Plan 04), UI gating is convenience |
| merge direction (loser vs winner) | A wrong-direction merge is an operator error with real impact; the type-to-confirm-the-loser guard mitigates it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-17 | Tampering (operator error) | MergeOrganizationsDialog | mitigate | Type-to-confirm the LOSING org's name + explicit winner selection; submit disabled until both satisfied — reduces wrong-direction merges. Merge is reversible anyway (clear the pointer). |
| T-36-18 | Elevation of Privilege | admin UI actions | accept | UI is reachable only in the ADMIN-scoped Admin Center; server-side has_role (Plan 04) is the real gate — a non-admin who reaches the UI still gets 403. |
| T-36-19 | Transparency | merge copy | mitigate | Copy states plainly that no recordings/memberships move and the operation is reversible — the operator is not misled into thinking data was migrated or destroyed. |
</threat_model>
