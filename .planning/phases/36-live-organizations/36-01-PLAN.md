claim_organization_domain(p_organization_id UUID, p_domain TEXT) RETURNS JSONB
  - GRANT EXECUTE TO authenticated (direct client .rpc() call, not an edge function)
  - Returns { "success": true } on success
  - Returns { "success": false, "code": "FORBIDDEN" }        when caller is not org admin/owner
  - Returns { "success": false, "code": "BLOCKLISTED" }      when domain is a free-email provider
  - Returns { "success": false, "code": "NO_VERIFIED_EMAIL" } when caller has no verified email on the domain
  - Returns { "success": false, "code": "CONFLICT" }         when domain already claimed (by ANY org; never names it)
  - NEVER RAISEs a raw unique_violation to the client; catches it and returns CONFLICT.

add_organization_alias(p_organization_id UUID, p_alias TEXT) RETURNS JSONB
  - GRANT EXECUTE TO authenticated; gated by is_organization_admin_or_owner
  - Returns { "success": true } / { "success": false, "code": "FORBIDDEN" | "CONFLICT" }
remove_organization_alias(p_alias_id UUID) RETURNS JSONB
  - GRANT EXECUTE TO authenticated; gated by is_organization_admin_or_owner on the alias's org
  - Returns { "success": true } / { "success": false, "code": "FORBIDDEN" | "NOT_FOUND" }

organization_domains: id, organization_id (FK organizations ON DELETE CASCADE), domain, claimed_by, claimed_at
organization_aliases: id, organization_id (FK organizations ON DELETE CASCADE), alias, created_by, created_at

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → claim_organization_domain RPC | Untrusted org id + domain string cross into a SECURITY DEFINER function; authority derived from auth.uid(), never a passed-in user id |
| org member → organization_domains/aliases SELECT | RLS is the enforcement line between orgs' identity metadata |
| claim RPC → identity_aliases (PII) | Reads verified-email rows under definer privilege; must not echo them back |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-01 | Information Disclosure | claim_organization_domain CONFLICT path | mitigate | Return a generic CONFLICT code only; never SELECT/echo the holding org's name or id; catch unique_violation so no raw Postgres message (which can include the conflicting value) escapes. Asserted by the integration test. |
| T-36-02 | Elevation of Privilege | claim/add/remove RPCs | mitigate | Authority validated inside the body via is_organization_admin_or_owner(p_organization_id, auth.uid()); RPC uses auth.uid() throughout, no spoofable p_user_id parameter. |
| T-36-03 | Tampering (policy bypass) | domain blocklist + uniqueness | mitigate | LOWER(TRIM(...)) normalization before every blocklist and uniqueness check and at storage; a real UNIQUE index on LOWER(domain) is the race-safe guarantee (Pitfall 3/4), not the application pre-check. |
| T-36-04 | Elevation of Privilege | organization_domains/aliases direct client writes | mitigate | No authenticated INSERT/DELETE/UPDATE policy exists; all writes go through the three GRANTed SECURITY DEFINER RPCs; FORCE ROW LEVEL SECURITY on both tables so even the table-owner role is subject to policy. |
| T-36-05 | Information Disclosure | cross-org SELECT of identity metadata | mitigate | member-SELECT policy via is_organization_member; proven by the two new CROSS_ORG_TABLES entries (a non-member JWT reads 0 rows). |
| T-36-SC | Tampering (supply chain) | package installs | accept | No npm/Deno packages installed this phase (RESEARCH Package Legitimacy Audit table is empty by design); no install task exists. |

Canon breadcrumbs (not minted here): SQL injection is covered by Supabase parameterized queries + /gsd-secure-phase; PII/retention for the reused identity_aliases email data is covered by /gsd-secure-phase — neither is a bespoke Phase-36 prohibition.
