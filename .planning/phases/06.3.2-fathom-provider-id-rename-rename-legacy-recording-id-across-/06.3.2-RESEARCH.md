## Security Considerations

- This rename touches RLS-adjacent SECURITY DEFINER functions (`delete_recording`, `global_search`, tag-rule functions, sharing functions). Recreate them with the same owner/security mode/search path and grants; do not accidentally drop `SECURITY DEFINER`, `SET search_path`, or `GRANT EXECUTE` clauses. [VERIFIED: live DB]
- `global_search` currently validates workspace membership and builds an escaped ILIKE query before returning accessible recordings. Preserve auth/member checks and escaped query logic while renaming metadata keys and joins. [VERIFIED: live DB]
- `delete_recording` checks `auth.uid()` against `owner_user_id` before deleting linked rows. Preserve authorization semantics when changing BIGINT bridge references. [VERIFIED: live DB]
- Integration tests must never point at production. `supabase/CLAUDE.md` documents a prior incident where integration tests mutated prod when env fallback existed; keep the triple-guard model intact. [VERIFIED: supabase/CLAUDE.md]
- Generated type files may expose token-column names but not values; do not treat type regeneration as a secret leak. [VERIFIED: docs/security/oauth-token-isolation.md]
- Do not broaden wildcard-CORS MCP endpoints or add session-cookie data while touching MCP read/write tools. [VERIFIED: AGENTS.md]
