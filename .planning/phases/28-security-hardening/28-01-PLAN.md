## Scope
- Timing-safe HMAC compare in zoom-webhook
- Timestamp replay window in zoom-webhook + polar-webhook
- Polar webhook idempotency via processed_webhooks

## Tasks

### Task 1: Timing-safe HMAC in zoom-webhook
- File: `supabase/functions/zoom-webhook/index.ts`
- Replace `expected === signature` (line 46) with `crypto.subtle.timingSafeEqual`
- Both strings need to be same-length Uint8Arrays for timingSafeEqual

### Task 2: Timestamp replay window in zoom-webhook
- File: `supabase/functions/zoom-webhook/index.ts`
- After signature verification passes, add timestamp validation
- Reject if `x-zm-request-timestamp` is >300s old or >60s in the future
- Return 401 with descriptive error

### Task 3: Timestamp replay check in polar-webhook
- File: `supabase/functions/polar-webhook/index.ts`
- Polar uses Svix under the hood — the `validateEvent` function already handles signature + timestamp
- Svix's default tolerance is 5 minutes — no additional code needed
- Document this decision in code comment

### Task 4: Polar webhook idempotency
- File: `supabase/functions/polar-webhook/index.ts`
- Generate webhook ID: `polar_${event.type}_${subscriptionOrCustomerId}_${timestamp}`
- Check `processed_webhooks` table before processing
- Insert after successful processing
- Wrap in try/catch so idempotency failures don't block event processing
