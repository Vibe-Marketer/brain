# Plan 41-03: Close 13 Deferred v2.0 Human-Verification Items

**batched by category** per Andrew's call. Every item ends in one of two states:

- `[x] Fixed (commit <hash>)` — code change was needed, made, and committed.
- `[~] Accepted (rationale)` — verified as working as designed (visual / interactive

## Process

For each cluster:

1. Open dev-browser to the relevant surface using
   `CALLVAULTAI_LOGIN` / `CALLVAULTAI_LOGIN_PASSWORD` from `.env.local` against
   `https://app.callvaultai.com`.
2. Walk through every item in the cluster.
3. For each item:
   - **If working as expected:** mark `[~] Accepted — verified live <date>`.
   - **If broken or partially broken:** create a fix commit, record hash, mark
     `[x] Fixed`. If the fix is too large for this phase (>2 files OR new
     feature scope), document the deferral as a new BACKLOG entry and mark
     `[~] Accepted — deferred to v2.3, see BACKLOG entry <id>` (this is the
     "documented acceptance" path Andrew's rules allow).
4. Write findings to `41-03-DEBT-03-AUDIT.md` as a complete table.
5. Append a compact status block to `STATE.md` under "Phase 41 — DEBT-03".
