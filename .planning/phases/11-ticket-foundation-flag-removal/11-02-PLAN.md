## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → send-support-ticket | untrusted JSON body crosses into Edge Function |
| Edge Function → DB (service-role) | RLS bypassed; code must enforce reporter identity |
| anon/authenticated JWT → PostgREST | direct table access governed solely by RLS |
| status UPDATE → audit trigger | SECURITY DEFINER write into append-only events table |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-04 | Spoofing | send-support-ticket insert | mitigate | reporter_id set exclusively from authenticateRequest userId; body-supplied userId field used only as legacy email metadata inside context JSONB, never as reporter_id |
| T-11-05 | Information Disclosure | tickets/ticket_messages/ticket_events cross-user reads | mitigate | RLS policies (reporter own / has_role ADMIN all); CROSS_ORG_TABLES regression probes ISC-4/5/6 in CI |
| T-11-06 | Tampering | unauthorized status changes | mitigate | UPDATE policy admin-only via has_role on USING and WITH CHECK; no DELETE policy on any ticket table |
| T-11-07 | Repudiation | lifecycle without audit trail | mitigate | AFTER UPDATE OF status SECURITY DEFINER trigger writes ticket_events; events table has no UPDATE/DELETE policies (append-only) |
