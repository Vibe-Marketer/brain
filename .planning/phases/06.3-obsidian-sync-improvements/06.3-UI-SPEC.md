# Phase 06.3: Obsidian Sync Improvements - UI Spec

**Created:** 2026-06-10
**Status:** Ready for planning

## UI Boundary

This phase keeps the existing Settings -> Integrations/API Tokens surface as the primary full-vault Obsidian export entry point. The user should be able to export a complete Obsidian vault archive without generating an API token.

## User Story

As a CallVault user with a large vault, I want one explicit action to export every call into Obsidian-compatible markdown so that I can own a local copy of my call knowledge without wondering whether some calls were skipped.

## Required Surfaces

### Settings API Tokens Section

- Keep the `Export vault` section above token generation.
- Primary button text remains `Download all calls` unless implementation needs a more precise label such as `Download Obsidian ZIP`.
- Button must show a busy state during export and prevent duplicate clicks.
- Empty vault result must use the existing toast pattern with `No calls to export`.
- Failure state must use a toast with a concise retry message and leave the button usable again.
- If export is split into multiple parts, the UI must make the part count explicit before or during download. Silent truncation is forbidden.

### Smart Export Dialog

- Keep `Obsidian Vault` as a selected-call export option.
- It remains a secondary/subset export path, not the full-vault canonical path.
- Workspace inclusion checkboxes are acceptable when exporting selected calls.

## Copy Rules

- Use "Obsidian ZIP", "full vault", "all calls", and "CallVault/" folder language.
- Do not say "AI-powered".
- Do not say "Obsidian token"; integrations use CallVault API tokens.
- Do not mention `obsidian-sync`.

## Interaction Requirements

- Full-vault export is one-click after the page loads.
- No token generation is required for browser ZIP export.
- If a 5,000-call export cannot safely be a single browser-generated file, show deterministic part downloads rather than hiding a cap.
- The user must never be told that only the first 500 calls were exported.

## Visual Constraints

- Use existing shadcn/ui `Button`, card/border, toast, and skeleton patterns.
- Use Remix Icons from `@remixicon/react` only.
- Keep this as a compact settings section, not a landing-page style surface.

## Accessibility

- Export button must remain keyboard reachable.
- Busy state must be represented by disabled state and visible text.
- Any multi-part export explanation must be plain text near the action, not only a toast.

## Verification

- Component or integration test verifies button disabled/exporting state and empty-vault toast.
- Browser smoke verifies the ZIP download path and resulting folder shape.
- If multi-part fallback is implemented, browser smoke verifies every part is downloaded or presented.
