### Required Post-Merge Tracking Gate

Run this gate immediately after every plan or review-fix worktree is merged into
`v2.2-event-resolution`, before starting the next plan:

1. Confirm the merged plan has its matching `SUMMARY.md` and committed implementation evidence.
   A STOP, blocked, partial, or in-progress summary does not count as completion even if the file exists.
   Require completed task counts and the plan's final PASS marker; require the phase verification report before closing a phase.
2. Run `gsd-sdk query roadmap.update-plan-progress <phase> <plan-id> complete` so `ROADMAP.md` is reconciled from the artifacts on disk.
3. Advance `STATE.md` to the next unfinished plan with `gsd-sdk query state.advance-plan`, then run `gsd-sdk query state.update-progress`.
4. Record the actual current status, blocker or review gate, and resume file in `STATE.md` through the registered `gsd-sdk query state.*` handlers.
5. Run `gsd-sdk query state.validate` and `gsd-sdk query roadmap.analyze`. Stop if either result disagrees with the plan and summary files on disk.
6. Commit the planning-file update separately and push `v2.2-event-resolution` to its matching remote branch as the checkpoint backup.

This gate is owned by the primary orchestrator. A plan executor writing its own
summary does not complete the central tracking update.
