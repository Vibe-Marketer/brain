## Evidence

- timestamp: 2026-04-07
  checked: WorkspaceJoin.tsx fetch flow (lines 51-113)
  found: Two-step lookup: (1) RPC get_workspace_invite_details for email invites, (2) direct supabase.from('workspaces').eq('invite_token', token).single() for shareable links. If step 2 returns no row OR error, sets error state → shows "This invite link is invalid or has already been used"
  implication: The failing token hits step 2. If workspaces RLS blocks the query, it silently returns {data: null, error: PostgrestError} → error state set

- timestamp: 2026-04-07
  checked: workspaces table SELECT RLS policies across all migrations
  found: ALL SELECT policies on workspaces require membership: "Users can view workspaces they belong to" uses is_workspace_member(id, auth.uid()), "Organization admins can view all organization workspaces" uses is_organization_admin_or_owner(). No policy exists for public/anonymous reads by invite_token.
  implication: A new user who is NOT yet a member of the workspace cannot SELECT the workspaces row, even by invite_token. Query returns null → error page.

- timestamp: 2026-04-07
  checked: Token format analysis + migration history
  found: DqiItwjxd7UARf8U3DvXw6dKRFX7LpLf is 32 chars, mixed case, base64-urlsafe charset → generated by generate_workspace_invite RPC which uses encode(gen_random_bytes(24), 'base64') with +→- /→_ =→'' substitution. Email invite tokens use 'hex' encoding = 48 chars.
  implication: This is definitely a shareable link token, stored in workspaces.invite_token

- timestamp: 2026-04-07
  checked: get_workspace_invite_details RPC (both original and renamed version in 20260301000001)
  found: Queries workspace_invitations table only — NOT workspaces.invite_token. So shareable link tokens always return empty from this RPC, falling through to the direct workspaces query.
  implication: The entire shareable link path has always been RLS-blocked for new users. The feature was never functional for its primary use case (inviting someone who isn't already a member).

- timestamp: 2026-04-07

  implication: The SELECT RLS gap was introduced at the feature's inception and never addressed.

## Resolution

root_cause: The workspaces table has no RLS SELECT policy allowing non-members to read a workspace row by invite_token. The shareable link join flow (WorkspaceJoin.tsx step 2) queried workspaces directly without bypassing RLS, so the query returned null for any user not already in the workspace → error state set → "This invite link is invalid or has already been used".
fix: Created SECURITY DEFINER RPC get_workspace_shareable_invite_details(p_token TEXT) that bypasses RLS and returns only invite-safe fields (workspace_id, workspace_name, organization_name, invite_expires_at). Returns zero rows if token is invalid or expired. Updated WorkspaceJoin.tsx step 2 to call this RPC instead of querying workspaces directly.
