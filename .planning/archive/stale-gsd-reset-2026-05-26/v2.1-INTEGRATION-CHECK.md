### ⚠️ WARNING #1: MCP `search_calls` org-scope does NOT search transcript content

**File:** `mcp-server/index.ts:953-1003` (org-scope branch)
**Affected REQs:** TOOL-01 (the spec says "full-text search scoped to org"), PASTE-03 (paste-source recordings should be discoverable)
**Severity:** WARNING — pre-existing gap, not a Phase 24 break, but worth flagging because the user brief says "FTS index covers paste-source full_transcript" and that's misleading in MCP context.

**Reality:**
- Workspace-scope `search_calls` calls `global_search` RPC, which only matches `r.title` (no `full_transcript` ILIKE — see migration `20260309200013_global_search_rpc.sql:142, 184`).
- Org-scope `search_calls` uses ILIKE on `recordings.title` and `recordings.summary` only — does NOT touch `full_transcript`.
- The frontend's `useGlobalSearch` (`src/hooks/useGlobalSearch.ts:230`) DOES ILIKE on `full_transcript` directly. So in-app "search bar" sees paste-source content; MCP `search_calls` does NOT.

**Effect:** A user who pastes a Fathom transcript and then asks Claude (via MCP) "what was discussed about pricing?" can only find the recording if "pricing" appears in the title or summary. To find it via transcript content, they must use `list_calls` + `get_transcript` discovery flow.

**Remediation options (defer to v2.2 unless launch-blocking):**
- Add `full_transcript ILIKE` to org-scope branch (line 967) and to `global_search` RPC (would need migration).
- OR document the title/summary-only behavior in `tools/list` description so MCP clients know to use `list_calls` + `get_transcript` for content search.
