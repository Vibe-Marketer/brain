    Exports:
    ```typescript
    export interface FathomSegment {
      start_ms: number;       // milliseconds from meeting start
      speaker: string;
      text: string;
    }

    export interface FathomParsedTranscript {
      title?: string;
      recorded_at?: string;   // ISO 8601 if detected from header
      attendees: string[];    // unique speaker names + invitees from header
      segments: FathomSegment[];
      parse_status: 'parsed' | 'raw';  // 'raw' = format unrecognized, segments=[]
    }

    /**
     * Extracts the share token from a Fathom share URL.
     * https://fathom.video/share/abc123XYZ → 'abc123XYZ'
     * Handles /share/, /share/h/, /share/i/, /share/p/, /share/u/ variants.
     * Returns null if URL is missing, malformed, or not a fathom.video URL.
     */
    export function extractShareToken(url: string | null | undefined): string | null;

    /**
     * Parses raw text from Fathom's "Copy transcript" button into structured segments.
     * Detects format by looking for `(M:SS)` or `(MM:SS)` timestamps.
     * If detected: returns parsed segments + auto-extracted title/recorded_at/attendees from header.
     * If NOT detected: returns { parse_status: 'raw', segments: [], attendees: [] } —
     *   caller saves raw text into full_transcript (no data loss, D-10).
     */
    export function parseFathomCopyFormat(rawText: string): FathomParsedTranscript;
    ```

    **Format spec to handle (per D-09 + BACKLOG.md):** Fathom's copy-transcript output looks like:
    ```
    Title: Q3 Sales Sync
    Date: October 5, 2026
    Attendees: Alice Chen, Bob Smith, Carla Diaz

    Alice Chen (0:00) Hey team, let's get started.
    Bob Smith (0:14) Thanks. So the numbers from last quarter are...
    Alice Chen (1:32) Wait, before we go further...
    ```

    Header section is optional and free-form (the format may include "Recorded at" or "Recording date" labels — match permissively). Speaker turn pattern: `^(.+?)\s+\((\d{1,2}):(\d{2})(?::(\d{2}))?\)\s+(.*)$` per line; multi-line turns concatenate until next speaker line. Convert `M:SS` or `MM:SS` or `H:MM:SS` to `start_ms`.

    Detection rule: if at least 2 lines match the speaker-timestamp pattern, treat as parsed; otherwise return `parse_status: 'raw'`.

    Attendees = union of (header-listed attendees) ∪ (distinct speaker names from segments). Deduplicate case-insensitively, return canonical form (first occurrence).

    Edge cases to handle gracefully:
    - Empty input → `{ parse_status: 'raw', segments: [], attendees: [] }`
    - Header-only (no timestamped turns) → `parse_status: 'raw'`
    - Trailing whitespace, CRLF line endings, multiple blank lines between turns
    - Timestamps without speaker name prefix (skip line)
    - No header at all (just speaker turns) → still parses, no title/recorded_at

    `extractShareToken` regex hint: `/^https?:\/\/fathom\.video\/share(?:\/[a-z])?\/([A-Za-z0-9_-]+)/`. Strip query string and hash before matching.

    Co-locate inline JSDoc with examples per export. Do NOT import zod here — keep zero deps.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → save-pasted-transcript | Untrusted user input crosses here: share_url, raw_transcript, title, attendees, bank_id |
| save-pasted-transcript → recordings table | Service-role write — must enforce workspace membership before write |
| pasted text → full_transcript / transcript_segments | User-supplied content rendered later in CallTranscriptTab — XSS surface if rendered as HTML |
| recordings.share_url → CallDetailHeader VIEW button | User-supplied URL becomes a `window.open` target — open redirect risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Spoofing | save-pasted-transcript | mitigate | Standard JWT verification via `supabase.auth.getUser`; reject 401 if token absent or invalid (per supabase/CLAUDE.md). |
| T-24-02 | Tampering | bank_id in request body | mitigate | Verify the authenticated user is a member of the requested `bank_id` via workspace_members lookup BEFORE writing. Reject 403 otherwise. Without this check, a user could inject another workspace's bank_id and write into someone else's space. |
| T-24-03 | Repudiation | recordings audit | accept | `created_at`, `synced_at`, `owner_user_id` capture who pasted what when. No additional audit log needed for v1. |
| T-24-04 | Information Disclosure | edge function error responses | mitigate | Return generic `{ error: 'Configuration error' }` style messages on 5xx. Never echo back the JWT, service key, or other request bodies. Log full details server-side only. |
| T-24-05 | Denial of Service | textarea size | mitigate | Zod max-length on `raw_transcript` (e.g. 5_000_000 chars ≈ 5MB) — refuse oversize payloads at the edge function with 413. Modal also enforces a soft limit client-side. Beyond that, Supabase request body limit (~6MB) is the backstop. |
| T-24-06 | Elevation of Privilege | upsert with onConflict | mitigate | Upsert filter `(bank_id, share_token)` is server-controlled — `bank_id` is from the JWT-validated workspace membership check, not directly from request body trust. Even if attacker passes someone else's bank_id, T-24-02 rejects them before reaching upsert. |
| T-24-07 | XSS via pasted transcript | CallTranscriptTab rendering | mitigate | Render `full_transcript` and `transcript_segments[].text` as plain text only — never `dangerouslySetInnerHTML`. Existing transcript rendering already does this (verify by grep during implementation). React's default escaping handles the rest. |
| T-24-08 | Open redirect via share_url | CallDetailHeader VIEW button | mitigate | Validate `share_url` server-side before storing: must match `^https?://(www\.)?fathom\.video/` per `extractShareToken` regex. Reject 400 otherwise. Defense-in-depth: client-side `window.open(url, '_blank', 'noopener,noreferrer')` (already standard in codebase). |
| T-24-09 | Legal — automated Fathom access | save-pasted-transcript | mitigate | ZERO outbound HTTP to fathom.video from any server-side code. Verified by grep gate in Task 2 verify block. Code review must confirm no `fetch`, no axios, no Deno HTTP client targeting fathom.video. The user pastes content themselves; CallVault is a notes app. |
