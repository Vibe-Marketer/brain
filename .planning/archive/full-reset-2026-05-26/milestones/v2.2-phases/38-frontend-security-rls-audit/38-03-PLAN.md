# Plan 38-03: Service-Role Rationale + Defense-in-Depth

## Objective

Annotate every edge function that uses `SUPABASE_SERVICE_ROLE_KEY` with a one-line `// service-role required: <reason>` comment immediately above the `createClient(url, SUPABASE_SERVICE_ROLE_KEY)` call. Audit each function's user-data queries for defense-in-depth `.eq('organization_id', ...)` or `.eq('user_id', ...)` filters. If any function cannot justify service-role usage, migrate it to anon+RLS.

## Scope (32 functions, from 2026-05-Q2-edge-audit.md Section B, post-Phase-37)

The 32 functions that currently use service-role but lack the rationale comment:

apply-routing-rules, auto-tag-calls, create-fathom-webhook, fathom-oauth-callback, fathom-oauth-refresh, fathom-oauth-url, fetch-meetings, fetch-single-meeting, file-upload-transcribe, generate-ai-titles, generate-content, global-search, polar-cancel, polar-checkout, polar-create-customer, polar-customer-state, save-host-email, share-call, split-recording, summarize-call, sync-meetings, teams, track-ai-usage, webhook, youtube-api, youtube-import, zoom-fetch-meetings, zoom-oauth-callback, zoom-oauth-refresh, zoom-oauth-url, zoom-sync-meetings, zoom-webhook.

Already annotated (skip): `mcp-server`, `polar-webhook`.
No service-role (skip): `mcp-oauth-metadata`, `mcp-oauth-register`, `send-org-invite`, `save-pasted-transcript`.

<action>
Defense-in-depth audit (SEC-04B). For each of the 32 functions, manually verify that every Supabase query touching user-data has an explicit `.eq('organization_id', ...)` or `.eq('user_id', ...)` (or equivalent owner-scoping filter) IN ADDITION to whatever RLS would catch.

Procedure per file:
1. Grep for every `supabase.from('...')` call in the file.
2. For each call that reads or writes user-scoped data (any table that has `user_id`, `owner_user_id`, or `organization_id`), verify the chain includes `.eq('user_id', userId)` or `.eq('owner_user_id', userId)` or `.eq('organization_id', orgId)`.
3. If a query touches a user-scoped table WITHOUT an explicit scope filter, add the filter. Use the variable names already established in the file (`userId`, `user.id`, `orgId`, etc.).
4. Webhook receivers (`polar-webhook`, `zoom-webhook`, `webhook`) are exempt — they receive data scoped to a webhook signature, not a user JWT, and the scoping is the `processed_webhooks` idempotency check.

Tables that DO NOT need scoping (pure config / lookup / public): `processed_webhooks`, `subscription_plans` (read), `tag_categories` (read), any table where the function is read-only and the data is public-by-design. Document any such exception inline.

For each filter that gets ADDED, mention it in the audit report (T03). Keep the change list tight — this task is primarily verification, not refactor.
</action>
