# Plan 35-05 — Drag-and-Drop Handle Stable + Enlarged

## Scope

- **DND-01** — The drag target is position-stable: it does NOT shift right when a row is selected (today the selection state visually pushes the handle).
- **DND-02** — Enlarge the drag target to occupy the left ⅓–½ of the row (centered around the title area), so users don't have to hit a tiny `⠿` glyph.

## Files

- `src/components/transcript-library/TranscriptTableRow.tsx` — the only file in scope. Uses `useDraggable` from `@dnd-kit/core`.

## Implementation

### Current state (TranscriptTableRow.tsx lines 127-142)

```tsx
<TableRow
  key={call.recording_id}
  ref={setNodeRef}
  {...attributes}
  className={cn("group h-7 md:h-8", isDragging && "opacity-50")}
>
  <TableCell className="align-middle py-0">
    <div className="flex items-center gap-1">
      {/* Drag handle — only this element triggers drag, not the whole row */}
      <span {...listeners} className="cursor-grab active:cursor-grabbing touch-none text-muted-foreground/40 hover:text-muted-foreground hidden md:inline-flex">
        ⠿
      </span>
      <Checkbox checked={isSelected} onCheckedChange={() => onSelectCall(call.recording_id)} />
    </div>
  </TableCell>
  <TableCell className="py-0 whitespace-nowrap">
    ...title button...
  </TableCell>
```

The `⠿` is tiny and lives in column 1. When the checkbox / selection orange pill appears, layout may shift slightly.

### Target design

1. **Hide the `⠿` glyph** — keep the visual minimal (the row already has a checkbox; an extra handle just clutters and shifts on selection).
2. **Make the title cell + its icon area the draggable** — apply `{...listeners}` to the title `<TableCell>` (or a wrapping `<div>` inside it). The title cell already spans ~⅓ of the row width, satisfying DND-02. The checkbox cell does NOT receive listeners (so clicking the checkbox doesn't start a drag).
3. **Stable positioning** — by moving the drag listeners off the small `⠿` and onto the larger title cell, the handle no longer "moves" when the row is selected because the entire title area is the handle. Selection changes the row background but the draggable area stays at the same coordinates.
4. **Avoid hijacking the title button** — wrap the title `<button>` and metadata so the *cell area around* them is the drag listener target. Clicking the title button still calls `onCallClick`; the drag fires when the user grabs empty space within the title cell (or holds + drags on top of the title — `dnd-kit` requires a small movement threshold so a click on the button still works).

### Concrete edits

**Step 1.** Remove the `<span {...listeners}>⠿</span>` element (lines 137-139). Keep the checkbox-only cell as:

```tsx
<TableCell className="align-middle py-0">
  <Checkbox checked={isSelected} onCheckedChange={() => onSelectCall(call.recording_id)} />
</TableCell>
```

**Step 2.** Move `{...listeners}` to the title `<TableCell>`. Apply `cursor-grab active:cursor-grabbing touch-none` to that cell:

```tsx
<TableCell
  {...listeners}
  className="py-0 whitespace-nowrap cursor-grab active:cursor-grabbing touch-none"
>
  <div className="space-y-0">
    <div className="flex items-center gap-1.5">
      <button
        onClick={(e) => {
          // Prevent dnd-kit pointer activation from firing on a click.
          e.stopPropagation();
          onCallClick(call);
        }}
        className="text-left hover:underline font-semibold text-xs md:text-sm truncate block max-w-[200px] md:max-w-[250px]"
      >
        {call.title}
      </button>
      <RoutingTraceBadge sourceMetadata={call.source_metadata} />
    </div>
    ... existing second-line metadata ...
  </div>
</TableCell>
```

**Step 3.** Configure activation distance so a click on the title button doesn't trigger a drag. `dnd-kit` `useDraggable` honors the `PointerSensor` activation constraint set at the DndContext root. Find the parent `<DndContext>` (likely in `TranscriptsTab.tsx` or the page that hosts the table + sidebar) and confirm a `PointerSensor` with `activationConstraint: { distance: 6 }` (or similar) is present. If absent, add one — see `dnd-kit` docs. **Action item:** during execution, `git grep "DndContext\|useSensor\|PointerSensor" src/` to find the root context and verify/add the activation distance.

**Step 4.** Mobile/tablet — `useDraggable({ disabled: isMobileOrTablet })` is already set. Confirm the cursor classes degrade gracefully on touch (they will — `cursor-grab` is a no-op on touch).

### Test Strategy

#### DND smoke test (real interaction, NO mocks)

1. **Without selection**: dev-browser drag a row by its title cell into a folder in the 2nd pane. Confirm the row lands and the call moves.
2. **With selection**: select the row first (checkbox), then drag by the title cell into a folder. Confirm:
   - The drag still works.
   - The handle position is unchanged from the unselected state (visually verify by holding a screen ruler / coordinates between the two screenshots).
3. **Click vs drag disambiguation**: click the title text → opens detail panel (no drag). Click the title cell whitespace + small mouse movement → drag.
