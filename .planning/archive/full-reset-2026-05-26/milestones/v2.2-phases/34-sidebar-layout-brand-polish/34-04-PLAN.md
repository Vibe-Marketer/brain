# 34-04 — Top-Bar Title Routing + ORGANIZATION Standardization

## QA-09 — Top-bar central title

Root cause: `src/components/Layout.tsx` `getPageLabel()` (lines 102-108) only handles `/`, `/people`, `/sorting-tagging`, `/settings`. Routes like `/organization`, `/import`, `/rules`, `/analytics`, `/transcripts` all fall through to default `'HOME'`. Per CONTEXT.md QA-09 every route should show its actual label.

## QA-10 — ORGANIZATION standardization

`src/components/panes/OrganizationCategoryPane.tsx` line 59 renders `<h2>Org</h2>` (rendered uppercase by CSS, so reads "ORG"). The page main pane header (`OrganizationPage.tsx` line 52-55) renders `title="Organization"` and the category overview (line 137) renders `title="Overview"`. Standardize on **ORGANIZATION** everywhere for the org route.

In `src/components/Layout.tsx`, REPLACE the entire `getPageLabel()` function (lines 102-108) with this expanded version that handles every primary nav route:

```tsx
const getPageLabel = () => {
  const p = location.pathname;
  if (p === '/' || p.startsWith('/transcripts')) return 'CALLS';
  if (p.startsWith('/import')) return 'IMPORT';
  if (p.startsWith('/rules')) return 'RULES';
  if (p.startsWith('/people')) return 'PEOPLE';
  if (p.startsWith('/organization')) return 'ORGANIZATION';
  if (p.startsWith('/settings')) return 'SETTINGS';
  if (p.startsWith('/analytics')) return 'ANALYTICS';
  if (p.startsWith('/call/')) return 'CALL DETAIL';
  if (p.startsWith('/sorting-tagging')) return 'SORTING & TAGGING';
  return 'HOME';
};
```

This means `/` now reads `CALLS` (matches the sidebar's first nav item per BRAND-01/BRAND-02). Per CONTEXT.md the top-bar title should "show the actual route" — the route at `/` IS the Calls library (TranscriptsNew), so `CALLS` is correct. If reviewers prefer `HOME` for the root, change the first line — but per BRAND-01 the route is logically Calls.

(Final decision per execute-phase QA pass — keep "CALLS" for `/` since that's what the sidebar entry is named.)
</action>
