## Phase 01 Interaction Contract

### Import Entry and Naming
- All user-facing manual-import entry labels in Phase 01 surfaces use `Import Transcript` (replace `Save Transcript` / `Paste Transcript` labels).
- Keep sidebar/global `Import` nav naming unchanged unless directly touched by the implementation path; no broad navigation redesign.
- The primary visual anchor is the `Import Transcript` CTA and the transcript-entry panel/modal it opens; source lists and import history remain secondary scanning surfaces.
- Visual hierarchy flows from CTA/title, to source/format selector, to transcript entry, to parsed preview, to submit/error footer. No upload/transcription card should compete with that path.

### Supported Manual Formats
- Supported transcript inputs for this phase: Loom, VTT, SRT, Otter TXT, Fathom copy, raw text, Markdown `.md`.
- Transcript file selector accepts only `.vtt`, `.srt`, `.txt`, `.md` (and matching text MIME types where applicable).
- Audio/video upload copy and entry affordances are removed from visible import flows.

### Parse and Fallback UX
- Apply best-effort parse language: partial parse is valid; never imply data loss.
- When speaker is missing or not confidently detected, render as `Unknown Speaker`.
- On parse failure, keep transcript intact and present a clear next step (review fields and import).
- Error states are inline and actionable; no stack traces or silent failures.

### Upload Removal Contract (MAN-06)
- Remove/hide `FileUploadDropzone` user entry points from Import page, source panes, and onboarding import cues.
- Keep compatibility behavior for existing historical `file-upload` records/internal metadata unless explicitly verified safe to remove.

### Feedback States
- `Idle`: primary button enabled only when minimum transcript content is present.
- `Submitting`: button text switches to progress state (`Importing…`) with spinner and disabled controls.
- `Success`: show concise confirmation toast and navigate/open imported call when ID is available.
- `Recoverable error`: inline warning/error panel with one clear user action.
- `Permission/auth error`: explicit session/workspace guidance.

### Accessibility
- Dialog controls are keyboard reachable, with visible focus ring (`--ring` / vibe orange).
- Error and warning banners use `role="alert"` and stay readable in both light/dark themes.
- Minimum touch targets preserve `44px` rule for mobile/touch interactions.
