<objective>
Harden the `?workspace_id` query parameter handling in `src/pages/OAuthConsentPage.tsx` per ISC-35–38 (HIGH security gate). The parameter must be validated against the currently selected org before auto-populating the workspace picker.

Purpose: An attacker can craft a consent URL with `?workspace_id=<uuid-from-org-B>` to lock the consent UI to a workspace the user did not intend to authorize. This is a pre-population injection attack.

NOTE: This plan and sec-dcr-phishing BOTH target OAuthConsentPage.tsx (D-16). If sec-dcr-phishing executes first and confirms the ISC-36 workspace guard is already present/correct, this plan becomes a verification-only pass with a comment added for traceability. If the guard needs hardening, implement it here.

Output: Confirmed or hardened workspace param validation in OAuthConsentPage.tsx.
</objective>
