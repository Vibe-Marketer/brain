## Areas Discussed

### Area 1: Plan Chunking Strategy

**Question:** How should 14 features map to GSD PLAN.md files?

**Options presented:**
1. One plan per wave/batch (4 plans)
2. One plan per feature (14 plans)
3. Hybrid

**Decision:** Option 2 — one plan per feature (14 plans). Fully independent, each plan tracks one atomic deliverable, max parallelism visible to executor.

**Rationale:** Wave gates go in frontmatter depends_on, not in task grouping. Keeps each plan bounded and independently executable.

### Area 2: Slug Backfill for Existing Orgs/Workspaces

**Question:** What happens to existing orgs/workspaces that have no slug yet?

**Options presented:**
- **Option A:** Auto-generate from org/workspace name on migration day. All existing orgs get subdomain URLs automatically.
- **Option B:** Leave slug NULL until admin explicitly sets one. No subdomain URL until then.

**Decision:** Option A — auto-generate slugs for all existing orgs/workspaces on migration day.

**Rationale:** Option B means zero existing users get the new feature on day 1, defeating the migration's purpose. Auto-generation from name is deterministic and safe: lowercase, strip non-alphanumeric, truncate to 40 chars, numeric suffix on collision. Tombstone tables prevent re-registration of any slug that was ever used, so auto-generated slugs are safe to treat as permanent. Documented in CONTEXT.md as D-06.

### Area 3: Consent Page Security UI Style

**Question:** How should client_id, first-time connection warning, redirect domain, and advisory text be rendered in OAuthConsentPage.tsx?

**Decision:** Use existing component patterns exclusively — no new custom components.
- **First-time warning:** Radix `Badge` with `border-amber-400 text-amber-700 bg-amber-50` styling, flanked by `RiErrorWarningLine` (already imported).
- **Client ID:** Truncated to first 8 + `…` + last 4 chars in a `<span className="font-mono text-xs">` inside the existing Card/CardContent layout.
- **Redirect domain:** Scheme + host only (not full path), in normal body text, flanked by `RiShieldCheckLine` (already imported).
- **Advisory text:** `"Only approve if you initiated this connection"` in `className="text-muted-foreground text-sm"` below the redirect domain.

**Rationale:** OAuthConsentPage.tsx already uses RiErrorWarningLine, RiShieldCheckLine, Card/CardContent, and brand-version v4.2 patterns. Amber badge matches the existing warning color conventions. Monospace truncated client_id follows standard OAuth consent UI patterns without introducing new dependencies. Documented in CONTEXT.md as D-15.
