<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public URL path -> MCP auth context | External resource URL determines internal authorization scope |
| Discovery metadata -> OAuth client | Clients rely on advertised protected-resource values to choose auth/resource targets |
| Worker proxy -> Edge Function | Public routing must preserve host/path accurately for downstream auth decisions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Elevation of Privilege | workspace audience binding | mitigate | Enforce path workspace cross-check in auth and return 403 on valid mismatches. |
| T-03-02-02 | Information Disclosure | `tools/list` on workspace endpoints | mitigate | Preserve category filtering after routing changes and test it in workspace-path coverage. |
| T-03-02-03 | Spoofing | protected-resource metadata | mitigate | Generate workspace-specific metadata from trusted host/path headers only. |
| T-03-02-04 | Denial of Service | unauthenticated discovery | accept | Keep wildcard discovery/CORS behavior per MCP requirements while maintaining bearer auth on data paths. |
</threat_model>
