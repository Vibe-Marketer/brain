# Phase 03 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | `default`, Tailwind base color `slate`, CSS variables enabled |
| Component library | Radix via shadcn primitives already in `src/components/ui` |
| Icon library | `@remixicon/react` only |
| Font | Inter for body/UI text; Montserrat only for compact section headings already matching Settings |

Implementation must extend the current Settings surface, not create a new app shell or marketing-style landing page. Use existing `Button`, `Badge`, `Select`, `Checkbox`, `Switch`, `Dialog`, `AlertDialog`, `Collapsible`, `Input`, `Label`, `Skeleton`, and `Separator` primitives. Do not add Lucide, FontAwesome, Heroicons, new animation libraries, or third-party shadcn registries.

Primary surfaces covered:

- Settings -> Integrations / AI connectors tab where OAuth-connected AI clients appear above manual/token-based connectors.
- OAuth consent page where the user picks organization scope by default and can optionally limit access to one workspace.
- Token reveal/setup dialogs and client snippets for workspace endpoint URLs.

---

## Layout Contract

| Surface | Layout |
|---------|--------|
| Settings AI connectors tab | Full-width Settings content with stacked sections. Use a two-column section header pattern on desktop: left column title/body, right column list/tool surface. Collapse to one column on mobile. |
| OAuth clients section | First section. Dense row list, not large marketing cards. Each row has provider/client icon, name, type badge, scope badge, workspace/org text, endpoint/resource URL, categories summary, last-used metadata, and revoke action. |
| Manual tokens section | Second section. Preserve current token row + collapsible permissions pattern. Copy positions manual tokens as controlled/fallback access, not the primary path. |
| Consent page | Centered single-panel authorization card with compact permission groups. Add workspace scoping controls inside the existing organization/access area. |
| Provider setup snippets | Inline setup panel or dialog attached to the selected org/workspace. Use tabs or segmented controls for provider-specific instructions when needed; do not put cards inside cards. |

Focal point:

- Settings: the top OAuth-connected clients section is the visual anchor. The primary CTA sits in that section header.
- Consent: the app/client name and selected access scope are the visual anchor. The approve CTA follows the scope summary.

Accessibility:

- Icon-only revoke/rotate/copy actions require `aria-label`.
- Scope badges must also be represented by text, not color alone.
- Workspace checkbox and dropdown must have persistent labels.
- Destructive revocation requires confirmation copy that names the client/token.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.3 |
| Heading | 16px | 600 | 1.25 |
| Display | 20px | 600 | 1.2 |

Rules:

- Use 12px uppercase labels only for compact section labels such as "OAuth clients", "Manual tokens", and "Permissions".
- Use 14px body text for descriptions, helper text, row metadata, and consent explanations.
- Use 16px headings for Settings section titles and dialog titles.
- Use 20px display only for the OAuth consent client name or a modal's primary title.
- Do not introduce hero-scale type, negative letter spacing, or viewport-scaled font sizes.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-viewport` / `bg-background` | Page background and authorization page background |
| Secondary (30%) | `bg-card`, `bg-muted/30`, `bg-muted/50`, `border-border/60` | Settings panes, rows, grouped permission panels, dialogs |
| Accent (10%) | `text-vibe-orange`, `border-vibe-orange`, approved `Button` primary styling | Primary CTA, active setup tab, focus ring, selected workspace-scope indicator, important endpoint copy action |
| Destructive | `text-destructive`, `border-destructive/30`, destructive AlertDialog action | Revoke OAuth client, revoke/delete manual token |

Accent reserved for: primary CTA, active tab/segmented option, focus ring, selected access-scope indicator, and the most important copy/setup action in a row.

Do not use accent orange for body text, broad backgrounds, or every interactive element. Secondary buttons, copy buttons, rotate actions, and neutral setup links use normal shadcn variants unless promoted as the single primary action for that screen.

State colors:

- Connected/active: use existing success semantic tokens or neutral badge with explicit "Connected" text.
- Needs refresh/reconnect: use warning semantic tokens with explicit "Refresh in client" or "Reconnect may be required" text.
- Revoked/error: use destructive semantic tokens and next-step copy.

## Interaction Contract

### OAuth Consent

1. Organization scope is selected by default.
2. The workspace checkbox is unchecked by default unless the flow started from a workspace-specific surface.
3. Checking the workspace checkbox reveals a workspace dropdown below the checkbox.
4. Unchecking the checkbox hides the dropdown and clears pending workspace-only selection in UI state.
5. Approval is disabled until an organization is selected and, when workspace scope is enabled, a workspace is selected.
6. The summary sentence updates live:
   - Org: `{client_name} can access non-admin MCP tools across {org_name}.`
   - Workspace: `{client_name} can access non-admin MCP tools for {workspace_name} only.`
7. Existing-consent fast paths must still show or reconcile CallVault's grant state before redirecting when possible.

### Settings AI Connectors

1. OAuth-connected clients render before manual tokens.
2. Each OAuth row shows:
   - client/provider name
   - connection type `OAuth`
   - scope `Organization` or `Workspace`
   - workspace/org name
   - endpoint/resource URL with copy action
   - categories summary, defaulting to `Read, write, AI` for non-admin OAuth
   - last used
   - created date/created by when available
   - revoke action
3. Manual token rows preserve category toggles and add prefixed-token display when available.
4. Manual token setup snippets must use `https://api.callvaultai.com/mcp/w/{workspace_uuid}` for workspace-scoped setup.
5. Provider-specific setup actions must be honest:
   - show `Connect with OAuth` only when CallVault can start the OAuth flow;
   - show `Copy setup` or `Open setup guide` for providers without verified one-click support;
   - never imply CallVault can silently install itself into a third-party AI client unless that provider has a verified path.

### Permission Changes

1. CallVault UI reflects server-side state immediately after mutation succeeds.
2. Rows with changed permissions show a small neutral/warning note: `Refresh may be required in {client_name}`.
3. Do not render disabled provider tools as a security promise. The copy must say CallVault rejects unauthorized requests server-side.
4. Revoke actions remove active access from the CallVault list immediately after success; revoked history can be added later only if the implementation already has a history affordance.

## Responsive Behavior

- Desktop Settings: section header grid can remain `lg:grid-cols-3`; content spans two columns.
- Tablet/mobile Settings: stack header and rows in one column; row actions wrap below metadata rather than compressing text.
- OAuth consent card: max width stays near current `max-w-md`; workspace dropdown must fit without horizontal scroll.
- Code snippets and endpoint URLs: use monospace blocks with `break-all` or horizontal scrolling so long URLs/tokens cannot overflow.
- Touch targets: use existing button sizing; icon buttons must remain visually stable and have accessible labels.
