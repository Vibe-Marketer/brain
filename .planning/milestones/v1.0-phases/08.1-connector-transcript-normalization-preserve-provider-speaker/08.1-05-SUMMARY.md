# Plan 05 Summary: Lazy Existing-Recording Normalization and Final Gate

## What Changed

- Chose lazy read-time normalization instead of a mutating DB backfill.
- Added `parseSpeakerTimestampTranscript()` to normalize existing Fathom/Zoom-style `full_transcript` text into display segments without writing rows.
- Updated call detail fallback parsing to reuse the shared helper after structured `transcript_segments` are checked first.
- Added tests proving parseable existing transcripts become structured display segments, unparseable text is skipped, and call-detail fallback stays read-only.

## Safety Decision

No DB migration or RPC was added in this plan.

Reason: the existing older `backfill_transcript_segments` RPC targets legacy `fathom_transcripts`, not the new `recordings.transcript_segments` JSONB contract. A new mutating backfill would require a dedicated real-DB proof run. Lazy normalization satisfies the phase safety rules by:

- filling no database columns
- creating no `recordings` rows
- creating no `workspace_entries` rows
- preserving `full_transcript` fallback
- preserving user-owned transcript edits because no persisted edited transcript state is overwritten
