# Phase 08.1: Connector Transcript Normalization - Validation

**Phase:** 08.1
**Date:** 2026-06-10
**Status:** Ready for planning

## Validation Architecture

Phase 08.1 changes the transcript source of truth for display/export surfaces. Validation must prove both new structured data paths and old fallback paths.

## Required Gates

1. Canonical contract tests
   - `supabase/functions/_shared/__tests__/canonical-recording.test.ts`
   - Proves `transcriptTurns` map to `recordings.transcript_segments` shape.
   - Proves `full_transcript` is still generated for fallback/search.

2. Provider normalization tests
   - Read.ai, Grain, Fireflies, PLAUD, Zoom, Fathom, YouTube, paste/manual, and MCP manual import fixtures.
   - Each fixture must assert speaker name, speaker email when provider supplies one, start/end offsets, duration, and expected participant identities.

3. Pipeline persistence test
   - `runPipeline()`/`insertRecording()` inserts `transcript_segments` when provided.
   - Participant helper upserts by normalized email/name and skips duplicate `Unknown`.

4. Call detail rendering test
   - `useCallDetailQueries` fetches/selects `recordings.transcript_segments`.
   - Structured segments are used before regex-parsing `full_transcript`.
   - YouTube/speakerless transcripts stay speakerless.

5. API/export contract tests
   - REST call detail and MCP `get_transcript` derive transcript markdown from structured segments when present.
   - Obsidian export uses participant names from canonical participants or structured segments.

6. Backfill/lazy-normalization test
   - Existing recordings normalize without creating new recording rows or workspace entries.
   - Existing user edits to transcript text/speaker names are not overwritten.

## Exit Criteria

- Every source listed in the roadmap has a documented normalization path.
- New imports persist structured segments.
- Existing records have a safe backfill or lazy-normalization path.
- Display, REST, MCP, Obsidian, and smart exports prefer structured segments and keep `full_transcript` fallback.
- Full verification includes `npm run type-check` and `npm run build`.
