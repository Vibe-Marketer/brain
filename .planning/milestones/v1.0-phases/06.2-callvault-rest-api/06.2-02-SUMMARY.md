# Phase 06.2 Plan 02: REST API Edge Function Summary

**One-liner:** `callvault-api` Edge Function with `token_source='api'` auth boundary, internal path router, and `{ data, pagination }` / `{ error: { code, message } }` response envelopes covering all five `/v1` endpoints.

---

## What Was Built

This plan implements the canonical CallVault REST API Edge Function. The `callvault-api` Supabase Edge Function handles all `/v1` read endpoints with scoped JSON responses and enforces the API token boundary (T-06.2-04, T-06.2-05, T-06.2-06).

### Auth (`auth.ts`)

`authenticateApiToken` reads the `Authorization: Bearer` header (case-insensitive), looks up the token in `mcp_tokens` without a source filter first (so unknown tokens return 401 rather than leaking that the token exists but is wrong-source), then enforces:

- Missing/malformed → 401 `MISSING_TOKEN` / `INVALID_TOKEN_FORMAT`
- Token not found → 401 `INVALID_TOKEN`
- Token found but `token_source != 'api'` → 403 `WRONG_TOKEN_SOURCE`
- Token revoked → 401 `TOKEN_REVOKED`
- Success → `ApiTokenContext` with `id`, `user_id`, `org_id`, `workspace_id`, `scope`, `name`
- `last_used_at` updated fire-and-forget after success

### Response Helpers (`responses.ts`)

Three exports:
- `jsonOk<T>(data, pagination)` — `{ data: T[], pagination: PaginationMeta }`
- `jsonItem<T>(data)` — `{ data: T }` for single-item responses
- `jsonError(status, code, message)` — `{ error: { code, message } }`

`PaginationMeta`: `{ count, has_more, next_cursor, limit }`

No MCP protocol patterns (`mcpOk`, `mcpError`, `jsonrpc`, `content[]`) anywhere in the production code.

### Routes

| Route | Handler | Scope |
|-------|---------|-------|
| `GET /v1/workspaces` | `handleListWorkspaces` | workspace → locked; org → all org workspaces |
| `GET /v1/calls` | `handleListCalls` | workspace_entries join, workspace/org filter, cursor pagination |
| `GET /v1/calls/{id}` | `handleGetCall` | UUID path param, workspace access check, returns transcript + participants |
| `GET /v1/contacts` | `handleListContacts` | user_id scoped (contacts schema ownership model) |
| `GET /v1/speakers` | `handleListSpeakers` | org_id via workspaces, deduped by name+email |

- `contract.test.ts` — 28 tests: route path registration, no MCP patterns, response envelope shapes, scope enforcement per handler, handler exports
