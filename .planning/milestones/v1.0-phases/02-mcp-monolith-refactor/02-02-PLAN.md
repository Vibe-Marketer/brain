<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| bearer token -> auth helper | Token family controls database visibility and identity |
| auth helper -> gate helper | Authenticated token context becomes authorization input |
| gate helper -> dispatcher | Category and subscription decisions determine tool reachability |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-02-02-01 | Elevation of Privilege | `auth.ts` | mitigate | Hex token lookup must stay on service-role client; tests anchor against anon-client regression from D-02. |
| T-02-02-02 | Spoofing | JWT auth branch | mitigate | JWT branch validates via Supabase Auth and does not treat arbitrary bearer strings as valid. |
| T-02-02-03 | Information Disclosure | protocol methods | mitigate | `initialize` and `tools/list` remain below valid-token auth. |
| T-02-02-04 | Information Disclosure | `gating.ts` | mitigate | Category gate remains before dispatch and fail-closes unknown tools for scoped tokens. |
| T-02-02-05 | Denial of Service | response helpers | mitigate | CORS preflight and non-POST probe handling remain lightweight and preserve current client discovery behavior. |
</threat_model>
