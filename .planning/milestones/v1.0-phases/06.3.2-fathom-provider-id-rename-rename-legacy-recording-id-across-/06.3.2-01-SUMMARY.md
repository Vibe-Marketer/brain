## Test/Local Schema Target

Production was not pushed during Plan 01.

Local Supabase full-stack replay was attempted with `supabase start`, but historical migration replay failed before this phase migration with:

```text
ERROR: relation "workspaces" already exists (SQLSTATE 42P07)
```

To keep Plan 01 isolated from production, a disposable local Postgres 16 database was created and seeded from the current linked schema-only dump:

```bash
docker run --name callvault-phase0632-db \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=postgres \
  -p 55432:5432 \
  -d postgres:16

supabase db dump --linked --schema public --file /tmp/callvault_public_schema.sql
```

The local database uses minimal local stubs for Supabase roles, `auth.users`, `auth.uid()`, `auth.jwt()`, `auth.email()`, and extension functions needed to restore the public schema. The current linked schema already had `fathom_provider_id`, so the disposable DB was converted back to the pre-migration local shape by renaming `fathom_provider_id` to `legacy_recording_id` and renaming the matching index/constraint back to their legacy names before applying the phase migration.
