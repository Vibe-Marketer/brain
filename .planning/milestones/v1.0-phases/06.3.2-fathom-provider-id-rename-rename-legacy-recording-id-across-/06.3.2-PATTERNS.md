# Phase 06.3.2: fathom_provider_id rename - Pattern Map

**Mapped:** 2026-06-10
**Files analyzed:** 40 active source/docs/test files + generated type file + migration analogs
**Analogs found:** 11 / 11 major file groups

## Scope Extracted

Phase 06.3.2 is a DB-first, compiler-driven rename of `recordings.legacy_recording_id` to `recordings.fathom_provider_id`. It must not rename `source_call_id`, must not edit historical migration files, and must preserve the numeric Fathom provider-ID semantics. `isLegacyId()` stays named as-is because it detects numeric ID format, not the DB column name.

Active exact-match inventory to plan against:

- Frontend/services/hooks/components/docs/tests, excluding generated types: 39 files with `legacy_recording_id`.
- `legacyId` helper/property consumers: 10 files.
- Generated DB type: `src/types/supabase.ts`.
- Historical migrations contain many old-name references and are read-only history. Use them only as analogs/source definitions when recreating live objects.

export async function resolveLegacyRecordingIdsToUuids(legacyIds: number[]): Promise<string[]> {
  if (legacyIds.length === 0) return []

  const { data, error } = await supabase
    .from('recordings')
    .select('id')
    .in('legacy_recording_id', legacyIds)

  if (error) throw error

  return (data || []).map((recording) => recording.id)
}
