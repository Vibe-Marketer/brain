# Phase 06 - UI Design Contract

> Visual and interaction contract for Launch UX + Support + RLS Hygiene. Generated by gsd-ui-phase, verified inline against CallVault v2 design rules.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui pattern |
| Preset | CallVault v2 AppShell / semantic Tailwind tokens |
| Component library | Radix primitives via existing `src/components/ui/*` |
| Icon library | `@remixicon/react` only |
| Font | Inter body, Montserrat headings |

Implementation must use existing AppShell panes, buttons, dialogs, popovers/dropdowns, tabs, toasts, and Remix icons. Do not add Lucide, FontAwesome, custom shells, custom token systems, or new page-level layout primitives.

---

## Surface Contracts

### 1. First-Run Import Landing

**Placement:** `/import`, inside existing `AppShell`.

**Pane model:**
- Pane 1: existing primary sidebar.
- Pane 2: existing `ImportSourcePane`; select the newly connected provider when route params identify it.
- Pane 3: connector import wizard/library for that provider.
- Pane 4: unchanged detail panel behavior; do not introduce a marketing-style interstitial.

**Initial state after trial:**
- Show founder onboarding video as a centered Radix Dialog once.
- Dialog must sit over the actual import page, not replace it.
- Dismissal reveals the provider library/search surface immediately.

**Provider library:**
- Header: compact PageHeader scale, not hero scale.
- Primary CTA after results: `Sync all`.
- Secondary CTA: provider-specific narrower action such as `Sync selected` or `Change range`.
- Historical import remains explicit; never auto-import all historical calls on OAuth return.

**All-time language:**
- Use "All available calls" where the provider supports an all-time fetch.
- If the provider requires a bounded range, use "Available calls" plus the current date/range control; do not promise "all-time" falsely.

### 2. Founder Onboarding Video

**Modal behavior:**
- Radix Dialog with `sm:max-w-3xl` or nearest existing modal size.
- Video area uses a stable `aspect-video` container with `bg-muted`; no layout shift before the embed loads.
- Primary close action: `Start syncing calls`.
- Secondary close action: icon close button in the dialog header.

**Copy:**
- Title: `Start with your call library`
- Body: `Watch the quick walkthrough, then sync the calls you want from your connected source.`
- If video URL is missing: show the same dialog shell with a concise fallback message and `Start syncing calls`.

**Persistence:**
- One-time first-run visibility can be localStorage/session-based for launch.
- Support popout action must always be able to reopen the video.

### 3. Support Popout

**Placement:** sidebar bottom section, directly above Settings, replacing the current separate `Take the tour` and `How it works` buttons.

**Trigger:**
- Expanded sidebar: existing nav-button style with `RiQuestionAnswerLine` or closest Remix support/help icon, label `Support`, description `Help and setup`.
- Collapsed sidebar: square icon button matching current collapsed nav treatment.

**Popover:**
- Use Radix Popover or existing dropdown/popover primitive.
- Opens beside the sidebar trigger, not as a full page.
- Width: 280-320px desktop. On mobile, use a dialog or sheet only if the existing popover cannot fit.
- Background `bg-popover`/`bg-card`, border `border-border/60`, radius consistent with current popovers. No nested cards.

**Action list, in order:**
1. `Watch the Onboarding Video` — `RiPlayCircleLine`
2. `Take the Tour` — `RiRouteLine` or current tour/help icon
3. `How It Works` — `RiInformationLine`
4. `Support Docs` — `RiBookOpenLine`, opens `https://docs.callvaultai.com` in new tab
5. `Submit a Ticket` — `RiMailSendLine`

**Ticket form:**
- Opens from the popout as either an inline expanded panel or small Dialog.
- Fields: message textarea, optional reply email if user email is unavailable.
- Submit button copy: `Send ticket`.
- Success toast: `Ticket sent to support`.
- Error toast: `Ticket could not be sent`.
- Do not show raw user/org/workspace IDs in the UI; attach them silently to the ticket payload.

### 4. Empty States

**Global rule:** each zero-data surface gets one primary CTA and at most one secondary text/button action.

**Calls / vault empty state:**
- Heading: `No calls yet`
- Body: `Connect a recorder to bring your calls into CallVault.`
- Primary CTA: `Connect a source`
- Secondary CTA where useful: `Import transcript`
- Remove copy that promises direct audio/video file upload.

**Contacts empty state:**
- Heading: `No contacts yet`
- Body: `Import calls to build contacts from attendees and speakers.`
- Primary CTA: `Connect a source`

**Workspaces/folders empty states:**
- When user is in structure-management surfaces, primary CTA can be `Create workspace` or `Create folder`.
- In onboarding or first-run surfaces, prefer `Connect a source` before structure creation.

**Settings tabs:**
- Empty states should point to the specific setup action for that tab. Avoid generic "No data" without action.

### 5. Billing / Paywall Gates

**Locked affordance:**
- Render gated actions in place with a lock icon (`RiLockLine`) and muted explanatory text.
- Do not hide important Pro/Team capabilities completely.

**Action attempt:**
- Open a Radix Dialog paywall.
- Dialog title: `Upgrade to keep going`
- Body: state the exact feature benefit in one sentence.
- Primary CTA uses existing `UpgradeButton` and passes a route-preserving `successPath`.
- Secondary CTA: `Not now`.

**Post-checkout:**
- Return to the same route/surface.
- If exact action replay is not implemented, the gated control must be usable after subscription refetch without logout or manual reload.

### 6. Optional Fathom Resync

**Import/search list states:**
- `Available`: selectable for import, normal row.
- `Imported`: muted row, not selected by Sync all.
- `Updated remotely`: normal contrast row with an outline/status badge and selectable for resync.

**Badge copy:**
- `Updated remotely`
- Secondary detail, if cheap: `Title changed` or `Transcript changed`.

**Primary action behavior:**
- If the list contains only available calls, primary CTA remains `Sync all`.
- If selected rows include remote-updated calls, CTA becomes `Apply updates`.
- Mixed selected rows may use `Sync and update` only if implementation supports both safely; otherwise split actions.

**Confirmation for title overwrite:**
- If a local title differs from provider title, show old/new values before applying:
  - `Current title`
  - `Fathom title`
- Primary CTA: `Update from Fathom`
- Secondary CTA: `Keep current title`

## Spacing Scale

Declared values use Tailwind spacing but must resolve to 4px multiples.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/text gaps, badge internals |
| sm | 8px | Button/icon spacing, compact row gaps |
| md | 16px | Dialog body gaps, form field groups |
| lg | 24px | Pane internal padding, modal padding |
| xl | 32px | Major section breaks inside Pane 3 |
| 2xl | 48px | Empty-state vertical breathing room |
| 3xl | 64px | Rare page-level center empty-state height |

Exceptions: existing AppShell pane gap is `gap-3` / 12px and remains binding.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 10-12px | 600 | 1.2 |
| Pane Heading | 14px | 800 | 1.2 |
| Dialog Title | 18-20px | 700 | 1.25 |
| Page Header | existing `PageHeader` scale | existing | existing |

Rules:
- Pane/section headings use `font-montserrat font-extrabold uppercase tracking-wide text-sm`.
- Body and explanatory text use `text-sm text-muted-foreground`.
- Metadata uses `text-xs text-muted-foreground`.
- Do not use viewport-scaled font sizes.
- Do not use negative letter spacing.
- Avoid hero-scale typography in panes, dialogs, support popouts, and setup widgets.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | semantic `bg-viewport` / `bg-card` | App shell, panes, dialogs, popovers |
| Secondary (30%) | semantic `bg-muted`, `border-border/60` | Hover states, empty-state icon wells, dividers |
| Accent (10%) | semantic `text-vibe-orange`, `bg-vibe-orange` | Active nav/pills, small status accents, page wayfinding |
| Destructive | semantic destructive token | Destructive confirmations only |

Accent reserved for: active navigation indicators, small status icons/badges, focus rings, page wayfinding, and high-value primary status cues. Do not use orange as paragraph text, full-panel fill, or generic decoration.

Status cues:
- Success/imported: existing success/emerald token usage.
- Remote update/resync: outline badge with vibe-orange icon or border, not a full orange row.
- Locked/paywall: muted text plus lock icon; primary upgrade CTA remains existing button styling.

## Interaction Contracts

### Keyboard and Focus
- Support popout trigger must be keyboard-focusable and close on Escape/outside click.
- Dialogs must trap focus through Radix and restore focus on close.
- Ticket form submit must be available via Enter/Cmd+Enter only if existing form conventions support it; otherwise keep button submit.

### Loading
- Video modal: stable placeholder while video loads.
- Provider fetch: existing button loading state, no full-pane blanking.
- Ticket submit: disable submit and show loading text/spinner.
- Paywall checkout: existing `UpgradeButton` processing state.

### Error States
- Provider fetch errors use toast plus inline retry affordance if already available.
- Ticket errors do not expose Edge Function internals.
- Missing video URL is a non-blocking fallback, not a broken embed.

### Responsive
- Desktop: support popout opens beside sidebar.
- Tablet/collapsed sidebar: popout remains anchored to icon and uses icon tooltip/aria label.
- Mobile: if sidebar is overlayed or insufficient width, support action may open a dialog with the same action list.

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn/ui local primitives | Button, Dialog, Popover/DropdownMenu, Textarea/Input, Badge, Tooltip as already present | Use existing local components only |
| Radix primitives | Dialog/Popover behavior through existing wrappers | No new unwrapped primitive unless no wrapper exists |
| Remix Icons | Support, video, tour, docs, mail, lock, update icons | `@remixicon/react` only |
| motion/react | Optional small dialog/popout entrance only | Use existing spring values if animated |

Do not install new UI libraries for Phase 6.
