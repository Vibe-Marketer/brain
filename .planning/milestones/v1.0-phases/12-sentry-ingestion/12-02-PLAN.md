<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → sentry-webhook | Unauthenticated, untrusted POST bodies claiming to be Sentry |
| sentry-webhook → ingest_sentry_ticket RPC | Verified payload fields cross into SECURITY DEFINER SQL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Spoofing | sentry-webhook ingress | mitigate | HMAC-SHA256 `sentry-hook-signature` over RAW body, constant-time compare via `timingSafeEqualString`; 401 before any DB work |
| T-12-02 | DoS | request body handling | mitigate | 512KB size cap + method gate + fast 200/401 paths; one RPC round trip total |
| T-12-06 | Information disclosure | error responses / logs | mitigate | Never log or echo SENTRY_WEBHOOK_SECRET or computed digests; generic 401 body |
| T-12-07 | Tampering (replay) | valid payload re-delivery | accept | Replay only inflates occurrence_count — no privilege or state escalation; optional sentry-hook-timestamp staleness check left to discretion |
| T-12-08 | Injection | payload strings → SQL | mitigate | Parameterized `supabase.rpc()` args only; zod length caps; no string-built SQL |
| T-12-SC | Tampering | package installs | accept | No new packages — esm.sh pins already in production use |
</threat_model>
