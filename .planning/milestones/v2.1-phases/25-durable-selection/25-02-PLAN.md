<objective>
Build the reconciliation hook that wraps the durable store and wires it to canonical server truth. `useImportSelection` is the UI-shape-independent React surface Phase 26's `<ImportSurface>` consumes: it exposes scoped toggle / select-all-matching / clear / isSelected / count, and — critically — it reconciles the selection against Phase 24's `getSyncStatusForExternalIds` so any selected call that has BECOME synced auto-drops from the selection (the second half of SEL-01). Reconciliation drops only synced ids; it never clears the selection on a background refetch (Anti-Pattern 1).

Purpose: Completes SEL-01 — the store (Plan 01) makes selection durable; this hook makes it correct against server truth without re-introducing the clear-on-fetch bug. It also gives downstream phases a single hook to call instead of touching the store directly.

Output: `src/hooks/useImportSelection.ts` + its test. This plan does NOT build the dense table UI (Phase 26). It MAY refactor `useSyncTabSelection.ts` to delegate to the new store ONLY if low-risk; otherwise leave the wiring to Phase 26 (decision recorded in the SUMMARY).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client selection (intent) ↔ server sync truth | The hook reconciles client INTENT against `recordings` via Phase 24's owner/org-scoped reader. The store is never the authority for "synced". |
| reconcile query ↔ org scope | `getSyncStatusForExternalIds` is owner_user_id-scoped with an optional `organizationId` filter (Phase 24). The hook threads `organizationId` so reconciliation cannot read another org's recordings. |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-04 | Information Disclosure | reconcile reading recordings cross-org | mitigate | Pass `organizationId` through to `getSyncStatusForExternalIds`; the reader is owner-scoped + org-filtered and fail-open (empty Map) for unauthenticated callers. The hook never widens scope. |
| T-25-05 | Spoofing/Tampering | trusting client store for "synced" | mitigate | "Synced" is ALWAYS read from `recordings` (server truth), never from the persisted store. A tampered store can over-select intent but cannot mark something synced or authorize an import (server RLS gates the actual write). |
| T-25-SC | Tampering | npm installs | accept | No new packages this phase (@testing-library/react + vitest already present). Nothing to verify. |
