<objective>
Build the single canonical, provider-agnostic "is this call synced?" reader on `recordings.(source_app, source_call_id)` (both TEXT, no numeric coercion), migrate the one broken call site off the Fathom-only `parseInt` path, and fix the related `cancelSyncJob` `error`-column bug in the same service file.

Purpose: The current `checkSyncedRecordingIds` calls `Number.parseInt(externalId)` on every id, silently dropping every UUID-id provider (Zoom, Fireflies, Grain, Read.ai, file-upload) so their already-synced rows never grey out and can be double-imported. IMP-01 replaces it with a reader that keeps ids as TEXT end to end. The reader is provider-agnostic (takes a `sourceApp` argument), but the SyncTab surface it serves is Fathom-only today — there is no `sourceApp`/`source_app` value anywhere in `useSyncTabState.ts` or `useSyncTabOrchestration.ts` to thread, so the call site passes the literal `"fathom"`. The `cancelSyncJob` fix is folded in here because this plan owns `sync-tab.service.ts` (single-writer rule for parallel execution).

Output: `src/services/sync-status.service.ts` (new), its unit test, deletion of `checkSyncedRecordingIds`, the rewired `useSyncTabStateBridge` call site + the `checkSyncStatus` signature change propagated to `useSyncTabState.ts` (the `UseSyncTabStateProps` interface + the line-202 invocation) and `SyncTab.tsx` (the wiring at line 138), and the `cancelSyncJob` `error`-column fix.
</objective>

|----------|-------------|

| user → cancelSyncJob → sync_jobs | A user cancelling a job writes a reason that must actually persist. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Information Disclosure | getSyncStatusForExternalIds | mitigate | Scope every query by `.eq("owner_user_id", user.id)` (from getSafeUser); optional org filter further narrows. The reader never returns rows outside the authenticated user's ownership. |
| T-24-02 | Tampering (SQL injection) | recordings `.in("source_call_id", externalIds)` | mitigate | Supabase `.in()` is parameterized; ids are never string-interpolated. Keep ids as TEXT — no string concatenation into SQL. |
| T-24-03 | Tampering (data integrity) | id coercion | mitigate | No `parseInt`/`Number()` on any id — enforced by the unit test grep assertion in Task 1. Coercion is the exact bug class being removed. |
| T-24-06 | Repudiation | cancelSyncJob silent error drop | mitigate | Fix the write to the real `error` column so a user-cancelled job actually records its reason (PostgREST was silently dropping the nonexistent error_message). |
</threat_model>
