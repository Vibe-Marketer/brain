    Edit `src/lib/user-friendly-errors.ts`. Add a new block at the TOP of `getUserFriendlyError` (immediately after `const errorMessage = error instanceof Error ? error.message.toLowerCase() : String(error).toLowerCase();`, BEFORE the "Auth/Session Errors" / "Invalid JWT" branch) that handles Supabase-Auth-specific substrings in this exact order:

    1. `errorMessage.includes('user already registered')` → return `{ title: 'Already Registered', message: 'This email is already registered. Sign in instead.', canRetry: false }`
    2. `errorMessage.includes('invalid login credentials')` → return `{ title: 'Wrong Email or Password', message: 'Invalid email or password. Check your spelling or reset your password.', canRetry: false }`
    3. `errorMessage.includes('password should be at least 6 characters')` → return `{ title: 'Password Too Short', message: 'Password must be at least 6 characters.', canRetry: false }`
    4. `errorMessage.includes('weak password')` → return `{ title: 'Weak Password', message: 'Try a stronger password — mix letters, numbers, and a symbol.', canRetry: false }`
    5. `errorMessage.includes('email rate limit exceeded')` → return `{ title: 'Too Many Attempts', message: 'Too many signup attempts. Try again in a few minutes.', canRetry: false }`
    6. `errorMessage.includes('over email send rate limit')` → return `{ title: 'Email Rate Limited', message: 'Too many emails sent. Wait a few minutes and try again.', canRetry: false }`
    7. `errorMessage.includes('email not confirmed')` → return `{ title: 'Confirm Your Email', message: 'Check your email and click the confirmation link to continue.', canRetry: false }`
    8. `errorMessage.includes('signup is disabled')` → return `{ title: 'Signups Paused', message: 'New signups are temporarily paused. Try again later.', canRetry: false }`
    9. `errorMessage.includes('email address is invalid') || errorMessage.includes('email address') && errorMessage.includes('invalid')` → return `{ title: 'Invalid Email', message: 'That email address doesn\'t look right. Check the spelling.', canRetry: false }`

    Order matters — Supabase-specific substrings must precede the generic `invalid` / `validation` / `email` branches so the generic chain doesn't swallow them first. All mappings use `canRetry: false` so `getErrorToastMessage` does NOT append `(...)` action suffixes — per UI-SPEC: "drop the `(Try Again)` suffix; this is an actionable redirect, not a retry."

    Add a one-line code comment above the new block: `// Supabase Auth-specific messages (Phase 31 AUTH-04 / QA-20) — match BEFORE generic substring chains`.
  </action>
