# Plan 38-05: CSP worker-src Fix

## Objective

Add `worker-src 'self' blob:` to the Content-Security-Policy header so blob: workers spawned by the app (transcript playback, analytics, etc.) stop being blocked at runtime. The current CSP omits `worker-src`, so the browser falls back to `script-src 'self' 'unsafe-inline' 'unsafe-eval'`, which then blocks `blob:` workers because `script-src` lacks `blob:`. The QA-07 finding shows ≥10 distinct blocked worker spawns across the route walk.

## Tasks

<task id="38-05-T01">
<action>
Edit `vercel.json` to extend the `Content-Security-Policy` header value. Currently:

```
default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; font-src 'self' data:; connect-src 'self' https://*.supabase.co wss://*.supabase.co https://*.sentry.io; frame-ancestors 'none'; base-uri 'self'; form-action 'self' https://fathom.video https://zoom.us https://marketplace.zoom.us
```

Change to (add the `worker-src` directive immediately after `script-src` — the position is conventional, not semantic):

```
default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; font-src 'self' data:; connect-src 'self' https://*.supabase.co wss://*.supabase.co https://*.sentry.io; frame-ancestors 'none'; base-uri 'self'; form-action 'self' https://fathom.video https://zoom.us https://marketplace.zoom.us
```

The added directive is exactly `worker-src 'self' blob:;` — no `'unsafe-inline'`, no `'unsafe-eval'`, no wildcards. This is the minimum required to unblock blob: workers without widening the attack surface.

Verify the JSON is still valid:
```bash
python3 -c "import json; json.load(open('vercel.json'))" && echo ok
```
</action>
