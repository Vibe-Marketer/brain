# Plan 38-02: npm audit Cleanup

## Objective

Drive `npm audit --omit=dev` to **zero high and zero critical** vulnerabilities. Document the remaining moderate findings with explicit accept/defer rationale. Add a CI gate that blocks merge on any future high/critical regression.

## Baseline (2026-05-12)

```
5 vulnerabilities (4 moderate, 1 high)
- lodash <=4.17.23 (high) — pulled via @tremor/react → recharts → lodash
- dompurify <=3.3.3 (moderate) — pulled via jspdf / docx
- esbuild <=0.24.2 (moderate) — pulled via vite (transitive, dev-tier path)
- postcss <8.5.10 (moderate)
- vite <=6.4.1 (moderate, breaking-change fix)
```

## Tasks

<task id="38-02-T01">
<action>
Add an `overrides` block to `package.json` that pins the transitive lodash to `^4.17.21` (the CVE-fixed line). Place the block at the root level of `package.json`, after `devDependencies`:

Expected output after fix: `critical=0 high=0 moderate=<=4 low=0`. If `high` is still > 0, the override didn't take effect — inspect `npm ls lodash` and adjust. The lockfile MUST be regenerated; commit both `package.json` and `package-lock.json`.

```json

    "postcss": "^8.5.10"
  }
```

Verify after install:
```bash
npm ls postcss
npm ls lodash
```
Both should show the bumped versions.

<task id="38-02-T04">
<action>
Add an `npm audit` CI gate to `.github/workflows/ci.yml`. The gate must fail the build on any new high or critical vulnerability. Append this job AFTER the `lint-typecheck` job:

```yaml
  # ─── npm audit (zero high/critical gate) ──────────────────────────────────
  npm-audit:
    name: npm audit (high/critical gate)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: npm audit --omit=dev (high+critical fails build)
        run: npm audit --omit=dev --audit-level=high
```

Note the existing `Security Review` workflow (`.github/workflows/security.yml`) already runs `npm audit --audit-level=moderate || true` — that one is informational. The new `ci.yml` job is the BLOCKING gate.

After the edit, validate the YAML:

