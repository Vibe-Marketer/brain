<action>
**QA-11 fix.** The current code:
```tsx
{org.cross_org_default ? org.cross_org_default?.replace('_', ' ') : 'None'}
```
Only replaces the FIRST underscore. So `copy_and_remove` becomes `copy and_remove` (only the first `_`). Plus `capitalize` only capitalizes the first letter ⇒ `Copy and_remove`. Hence the visible "Copy And_remove" leak.

Fix: use `.replaceAll('_', ' ')` (or a regex `/_/g`) AND map to proper human-readable labels:

```tsx
const labelMap: Record<string, string> = {
  copy_only: 'Copy only',
  copy_and_remove: 'Move (copy and remove from original)',
}
const label = org.cross_org_default ? (labelMap[org.cross_org_default] ?? org.cross_org_default.replaceAll('_', ' ')) : 'None'
```

Drop the `capitalize` Tailwind class since the map already provides correct casing. Apply the same fix anywhere else this enum is rendered (grep for `cross_org_default` in src/).
</action>

<action>
**QA-13 fix.** Cmd+K search takes 3–4s. Two layers to attack:

1. **Client-side debounce check** — verify the search query is debounced ~150ms (not 0ms = chatty, not 800ms = perceived as slow). If using `useDebouncedValue`, set debounce to `150ms`. If no debounce exists, add one.

2. **Loading state UX** — show optimistic UI: keep the previous result list visible (greyed) while new results load, AND show a small "Searching..." indicator in the input row. The current spinner blocks the whole panel which makes 1.5s feel like 4s.

3. **Server-side**: Inspect the search Edge Function. If it's doing a sequential SELECT * across multiple tables, look for low-hanging optimizations: (a) add a database index on the search text columns (defer to migration if not already in place), (b) limit the SELECT to N=20 results, (c) cancel in-flight requests when a new keystroke comes in (use AbortController).

For Phase 36 (bug sweep), implement (1) and (2) at minimum. (3) is a stretch goal — only do if a quick win is visible. If the Edge Function uses pg_trgm or full-text search already, no migration is needed.
</action>
<acceptance_criteria>

- Loading state shows previous results greyed + a subtle "Searching..." indicator (not a full-panel spinner)
- AbortController used to cancel stale in-flight searches
- Dev-browser: type "Sammy" — first chars feel responsive (< 200ms feedback), full results land in < 2s on typical queries
