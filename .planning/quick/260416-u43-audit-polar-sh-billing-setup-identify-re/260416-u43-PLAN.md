## 2. CRITICAL: Product ID Mismatch
The code uses SYMBOLIC product IDs ("pro-monthly", "pro-annual", "team-monthly", "team-annual") but the ACTUAL Polar product IDs are UUIDs:
- Pro Monthly: `30020903-fa8f-4534-9cf1-6e9fba26584c`
- Pro Annual: `9ff62255-446c-41fe-a84d-c04aed23725c`
- Team Monthly: `88f3f07e-afa3-4cb1-ac9d-d2429a1ce1b7`
- Team Annual: `6a1bcf14-86b4-4ec9-bcbe-660bb714b19f`

These UUIDs are documented in `.planning/archive/pre-antigravity-2026-03/13-strategy-pricing/POLAR-UPDATE-LOG.md` Section 9 but are NOT used anywhere in the code. `PlanCards.tsx` passes "pro-monthly" to `UpgradeButton`, which passes it to `polar-checkout`, which passes it to `polar.checkouts.create({ productId })`. Polar's API expects a UUID, not a symbolic name. This means EVERY checkout attempt will fail.

Determine: Is there a mapping layer somewhere that translates these? Or is this a blocking bug? Search the entire codebase including `_shared/` for any product ID mapping, constants file, or environment variable that holds UUIDs.
