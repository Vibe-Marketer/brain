<objective>
Consolidate `MoveToWorkspaceDialog` (workspace-centric, cross-org-aware) and `CopyToOrganizationDialog` (org-centric) into one `MoveOrCopyDialog`: pick an organization (defaults to current, `+ New Organization`) → pick a workspace scoped to that org (`+ New Workspace`) → toggle Move vs Copy. Wire it into the row More-actions menu, the bulk-selection toolbar, and the call detail header (net-new there), then retire both old dialogs.

Purpose: one predictable entry point for every move/copy operation, no duplicated dispatch logic, and a move option on the call detail page for the first time.

Output: `MoveOrCopyDialog.tsx` + its test, three rewired call sites, two deleted dialogs and one deleted test.

Key architectural fact confirmed by investigation: the service dispatcher `moveRecordingsToTargetWorkspace` and the `useMoveRecordings` hook ALREADY handle all four cases correctly based on `target.organizationId` vs `sourceOrgId` and `keepInSource`:
- same-org → `moveRecordingsToWorkspace` (workspace_entries upsert to target; deletes source entry only when `keepInSource=false`)
- cross-org → `copy_recording_to_org` RPC per recording with `p_delete_original: !keepInSource`
So NO service or hook changes are needed. This is a pure component consolidation + rewiring. Same-org "copy" IS meaningful — `workspace_entries` lets one recording row appear in multiple workspaces within the same org; `keepInSource=true` produces exactly that (adds target entry, keeps source).
</objective>
