# OAuth Token Client-Side Isolation Audit (SEC-03D, Phase 38)

**Audited:** 2026-05-12
**Scope:** Every reference in `src/` to a provider OAuth token (Google, Fathom, Zoom) — `access_token`, `refresh_token`, `oauth_access_token`, etc.

## Acceptance Standard

Only the **Supabase JWT** (`session.access_token`) is allowed in client memory. All provider OAuth tokens MUST stay server-side (in `user_settings` / `import_sources`, encrypted at rest per Phase 37 SEC-09).

## Grep Audit (raw command)

```bash
grep -rn "access_token\|refresh_token" src/ | grep -v "src/types/supabase.ts" | grep -v "\.test\."
```

### Supabase Types (auto-generated, ignored)

`src/types/supabase.ts` references the provider token columns by NAME because they exist on the DB schema. Out of scope for this audit.

## Deferred Items

### Zoom "refresh token presence" signal

Pre-Phase-38 `useIntegrationSync` had a subtle behavior: if Zoom's access token had expired BUT a refresh token was still present, the platform was considered "connected" (because the server-side refresh job would mint a fresh access token on next sync). To detect refresh-token presence the hook selected `zoom_oauth_refresh_token` and checked nullness.

Post-Phase-38 we no longer select the refresh token. Instead we rely on the server-side refresh job (`zoom-oauth-refresh`) to NULL out `zoom_oauth_token_expires` if the refresh path fails. So the connection signal becomes: "is `expires` non-null and > now?".

**Risk:** if the refresh job fails to null the column on failure, the client will show "connected" briefly. The next sync attempt fails and the user re-authenticates. This is acceptable.

**Cleaner fix (deferred to v2.3):** add a server-side derived `has_zoom_refresh_token` boolean view OR a `get_integration_status(user_id)` RPC that returns the connection booleans directly. Tracked as v2.3 BACKLOG item "OAuth integration-status RPC".

## Result

**SEC-03D acceptance:** PASS. Every client-side OAuth-provider-token read has been either:
- Replaced with a `*_token_expires` timestamp (5 sites).
- Confirmed acceptable (null-writes for disconnect, Supabase session JWT use).

No raw provider OAuth token (Fathom / Google / Zoom) is pulled to the client outside the documented null-write contexts.

## Encryption-at-rest reference

OAuth tokens stored in `user_settings.oauth_access_token`, `zoom_oauth_access_token`, etc. are encrypted at rest as of Phase 37 SEC-09 (`store_encrypted_oauth_tokens` RPC + `OAUTH_ENCRYPTION_KEY` env var). See `.planning/security/2026-05-Q2-token-encryption-baseline.md` for the runbook. Even if a future client-side leak occurred via this audit, the data at rest would be ciphertext.
